# 06 · 异步：程序可以先等一个结果

目标：理解 Promise 表示未来结果，能用 await 接收成功或处理失败。

运行：`node examples/js/06-async.js`。示例只用本地定时器模拟接口，不需要网络。

## 1. 为什么需要等待

读取网络数据不能保证立即完成。Promise 表示一项可能仍在进行的操作：pending 表示待定；fulfilled 表示成功；rejected 表示失败。已经确定的状态不会再变回待定。

```js
function wait(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}
async function loadTasks() {
  await wait(20);
  return [{ id: 1, title: "学习异步", done: false }];
}
```

`setTimeout` 请运行环境稍后调用函数，时间是近似的最低延迟，不是精确承诺。`new Promise` 此处把回调式接口包装成 Promise；平时调用已返回 Promise 的 API 不需要再包一层。

async 函数总是返回 Promise。即使函数里 `return 3`，调用方拿到的也是会成功得到 3 的 Promise，而不是立即得到数字 3。

## 2. await 暂停的是当前异步流程

```js
console.log("A");
const promise = loadTasks();
console.log("B");
const tasks = await promise;
console.log("C", tasks.length);
```

顺序是 A、B、C。await 等到结果后才继续这条流程，但不会把整个运行环境卡死。本项目使用 ES Modules，所以 Node 示例可以在文件顶层使用 await；普通非 async 函数体里不能直接这样写。

## 3. 成功与失败都要处理

```js
try {
  const tasks = await loadTasks();
  console.log(tasks);
} catch (error) {
  console.log(error instanceof Error ? error.message : String(error));
}
```

await 一个被拒绝的 Promise 会抛出该拒绝原因，由 catch 接住。忘记 await 可能导致你在结果到达前就访问数据，也可能让异步错误逃出当前 try / catch。

两个任务互不依赖时可以 `await Promise.all([loadTasks(), loadTasks()])`。其中一项拒绝时整体拒绝，但这不会自动取消其他已启动操作。先学清单次调用，再考虑并发。

## 4. 与真实请求的联系

真实 fetch 常见流程是 `const response = await fetch(url)`，先检查 `response.ok`，然后 `await response.json()`。HTTP 404 / 500 通常不会让 fetch 自己拒绝；网络失败与 HTTP 错误要区分。这里仅解释流程，不连接真实服务。

## 练习

把示例中的 `loadTasks(false)` 改成 `loadTasks(true)`，观察失败信息。再在 await 前后分别打印“开始等待”“拿到数据”。扩展练习：调用两次加载，分别尝试顺序 await 与 Promise.all，解释它们的依赖关系，不依赖精确计时判断正确性。

## 验收

能解释为什么 `const tasks = loadTasks()` 不是任务数组；能让失败路径也正常结束。
