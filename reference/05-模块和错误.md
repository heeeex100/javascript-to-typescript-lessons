# 05 · 模块、JSON 与错误：把程序拆成可理解的部分

目标：跨文件复用函数，把 JSON 文本转换成数据，理解异常流程。

运行：`node examples/js/05-modules.js`。

## 1. 一份文件负责一部分工作

`examples/js/lib/tasks.js` 通过 export 暴露函数，`05-modules.js` 使用：

```js
import { pendingTitles } from "./lib/tasks.js";
console.log(pendingTitles([{ title: "练习", done: false }]));
```

`./` 相对于当前这个源文件，不是相对于终端目录。本项目使用 ES Modules，根目录 package.json 的 `"type": "module"` 使其中的 `.js` 文件按该方式处理；本教程给本地导入路径写完整的 `.js` 后缀。

具名导出 `export function pendingTitles...` 与 `import { pendingTitles }` 配对。默认导出是另一种语法，暂时不用混学。

## 2. JSON 是文本格式

```js
const text = '{"title":"学习","done":false}';
const task = JSON.parse(text);
console.log(task.title);
console.log(JSON.stringify(task));
```

JS 对象存在内存里，JSON 是表示数据的文本。JSON 属性名和字符串必须用双引号；不能写注释、函数或 undefined。

`JSON.parse` 只保证文本符合 JSON 语法，不保证内容符合你的任务结构。`JSON.parse("123")` 完全合法，但结果不是任务对象。

## 3. 失败如何传播

```js
try {
  const value = JSON.parse("这不是 JSON");
  console.log(value); // 不会执行
} catch (error) {
  console.log("解析失败：", error.message);
}
```

发生异常后，当前正常路径中断，程序寻找可处理它的 catch。需要主动拒绝输入时可写 `throw new Error("分钟数无效")`。不要只打印错误后假装处理成功：调用方需要明确知道失败。

上面演示的是 JSON.parse 抛出的 Error 对象。JS 可以 throw 其他值；到 TS 部分会用 `error instanceof Error` 检查后再读取 message。

## 4. 调试顺序

先复现，再读报错文件及行号，打印最小必要的中间值，最后验证修正。第 03 课闭包可观察 count；第 04 课可分别打印 filter 前后数组。若使用 VS Code，可在运行和调试面板创建 Node 调试配置，给当前文件的可执行行打断点，再逐步执行。
