# 11 · 泛型：保留输入与输出之间的类型关系

目标：写可复用函数时不丢失类型信息，理解约束的作用。

运行：`npm run build`，然后 `node dist/examples/ts/11-generics.js`。

## 1. 先看具体问题

你想从任意数组里取第一项。分别写 firstNumber、firstString 会重复；返回 any 又会丢失提示与检查。泛型可以表达“传入什么元素类型，就返回该类型的元素或 undefined”。

```ts
function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}
const a = first([10, 20]);     // number | undefined
const b = first(["JS", "TS"]); // string | undefined
```

T 是类型参数，调用时由编译器根据实参推断，也可写 `first<number>([])` 明确空数组的元素类型。T 不会变成运行时变量。

返回 undefined 是因为空数组没有第一项。不要为了让调用更方便就写成永远返回 T。

## 2. 需要某种能力，就声明约束

```ts
function findById<T extends { id: number }>(
  items: readonly T[],
  id: number,
): T | undefined {
  return items.find(item => item.id === id);
}
```

extends 在这里限制 T 至少有数字类型的 id。函数能读取 id，同时保留原来的完整元素类型。它不意味着必须实例化某个父类。

## 3. 与 keyof 建立关联

```ts
function getProperty<T, K extends keyof T>(value: T, key: K): T[K] {
  return value[key];
}
```

keyof T 表示 T 的属性名类型；K 只能从这些属性名中选择；T[K] 表示该属性的值类型。传入任务和 `"title"` 得到 string，传错属性名会报错。

先把它读成中文：“给我一个对象和它的一个合法键，我把对应值按正确类型还给你。”理解之后再记语法。

## 4. 常见工具类型

`Pick<Task, "title" | "done">` 选择字段；`Omit<Task, "id">` 排除字段；`Partial<Task>` 让字段变为可选；`Readonly<Task>` 将直接属性标为只读。它们改变类型描述，不会自动复制、删除、转换运行时对象。

不要为了使用泛型而使用泛型。如果函数只处理任务，直接写 Task 通常更清楚。泛型适合表达多个位置之间重复出现的类型关系。
