# 10 · 联合类型与收窄：不同情况，走不同分支

目标：消除不可能的状态，安全处理未知输入。

运行：`npm run build`，然后 `node dist/examples/ts/10-narrowing.js`。

## 1. 联合表示“可能是其中之一”

```ts
function normalizeId(id: string | number): string {
  if (typeof id === "number") {
    return id.toFixed(0);
  }
  return id.trim();
}
```

进入 if 分支后，编译器知道 id 是 number；另一个分支里知道它是 string。通过判断缩小可能类型的范围叫收窄。typeof、instanceof、属性检查、字面量判别等都可以参与收窄。

## 2. 用状态描述结果

```ts
type Result =
  | { ok: true; value: number }
  | { ok: false; error: string };

function describe(result: Result): string {
  if (result.ok) return `结果是 ${result.value}`;
  return `失败：${result.error}`;
}
```

这里 ok 不是任意 boolean，而是两个分支各自固定的字面量。成功必定有 value，失败必定有 error，比把所有字段都写成可选更容易正确使用。

如果增加第三种状态，switch 配合 never 可以让编译器提醒你补全处理；综合项目保持两种状态，先理解基本思路。

## 3. any 与 unknown

any 大量关闭类型检查，可能让错误一路通过。unknown 表示“暂时不知道它是什么”，要求先检查再使用，适合外部数据边界。

```ts
const raw: unknown = JSON.parse('{"title":"学习"}');
if (typeof raw === "object" && raw !== null && "title" in raw) {
  if (typeof raw.title === "string") {
    console.log(raw.title.trim());
  }
}
```

JSON.parse 的类型声明返回 any；主动接到 unknown 上，要求后续代码先建立证据。检查 typeof object 时同时排除 null；检查属性存在后还要检查属性值的类型。

## 4. 类型断言没有校验能力

`raw as Task` 是让编译器按 Task 看待它，不会补字段、转换值，也不会阻止错误输入。`value!` 同样只是告诉编译器忽略空值可能性，不会自动处理 null。

当检查逻辑重复时可写类型守卫 `function isTask(value: unknown): value is Task`。这种返回声明是一份承诺，编译器不会替你证明检查逻辑覆盖了全部字段，必须自己写对。

## 练习

在 `exercises/ts.ts` 完成 `parseTitle(value: unknown)`：只有非空字符串成功，返回去除两侧空白后的值；其他输入返回 `{ ok: false, error: "标题不能为空" }`。

扩展：阅读 `project/validation.ts`，找到它如何拒绝缺失字段、非法 id 和重复 id。把一条 JSON 的 done 改成字符串 `"false"`，确认校验失败，不能简单用 Boolean 转换，因为 `Boolean("false")` 是 true。
