# 09 · 对象类型：给数据结构写一份约定

目标：描述任务结构，区分可选属性、只读属性和运行时行为。

运行：`npm run build`，然后 `node dist/examples/ts/09-models.js`。

## 1. 定义结构并复用

```ts
interface Task {
  readonly id: number;
  title: string;
  done: boolean;
  note?: string;
}
const task: Task = { id: 1, title: "学习 TS", done: false };
```

id、title、done 必须存在并符合类型；`note?` 表示该属性可以不提供。读取 note 时要考虑 undefined，例如 `task.note?.trim() ?? "无备注"`。

readonly 阻止通过该类型直接赋值给 id。它不是运行时冻结，也不会自动让所有嵌套对象不可变。要保护运行时对象，需要另行设计更新方式或使用冻结等机制。

## 2. type 和 interface 怎么选

```ts
type TaskId = number;
type Filter = "all" | "pending" | "done";
type TaskSummary = { id: TaskId; title: string };
```

type 可以给联合类型、对象类型等起名字；interface 主要描述对象形状，也支持扩展与声明合并。初学时用 interface 描述对象、type 表达联合即可，后续再学习边界差异。

不要把 TaskId 当成新建了一种与 number 完全隔离的运行时类型，它这里只是 number 的别名。

## 3. 结构兼容性

```ts
function showTitle(value: { title: string }): string {
  return value.title;
}
showTitle(task); // task 具有所要求的 title
```

不要求 Task 显式声明继承某个 Showable 接口。但是直接传入对象字面量时，额外属性检查可能报告拼错或多余的属性；不要据此认为“对象永远不能有更多字段”。

## 4. 数组、空值和函数签名

`readonly Task[]` 允许读取任务列表，却禁止通过这个数组引用 push 或替换元素；不会自动让元素的所有字段只读。`Task | undefined` 表示可能找到任务，也可能没有。

```ts
function findTask(tasks: readonly Task[], id: number): Task | undefined {
  return tasks.find(task => task.id === id);
}
```

调用方要判断返回值是否存在，不能直接假设 find 一定成功。
