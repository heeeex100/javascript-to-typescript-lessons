### 泛型、类型参数与类型关系

**泛型**让一段实现适用于多种类型，同时保留输入和输出之间的联系。类型参数 T 是占位名，不是运行时变量，也不是固定的一种类型。

- **调用时确定类型**：`identity(3)` 推断 T 与数字相应，`identity("JS")` 推断字符串。也可显式写类型参数，例如 `identity<string>("JS")`。
- **关系比范围更重要**：`(value: T) => T` 表达“返回与输入对应的类型”；使用 any 会丢掉这种联系。
- **联合不是泛型的替代品**：输入写 string 或 number、返回也写这两者的联合，未必告诉调用方“输入字符串时一定返回字符串”；泛型能表达这个关系。
- **空集合**：如果从数组取第一项，数组可能为空，返回类型应承认 T 或 undefined。类型签名要反映真实可能结果，不能假定一定有值。
- **泛型约束**：只有对所有 T 都安全的操作才能直接使用；要读取 id 等成员，就用 extends 声明 T 至少具有该结构。

<summary>读例子 → 改一个地方 → 检查理解</summary>

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
const title = first(["JS", "TS"]);
const count = first([1, 2]);
const missing = first<number>([]);
console.log(title?.toUpperCase(), count, missing);
```

**逐步理解**：输出“JS 1 undefined”。title 与 count 保留了各自元素的类型，但都需要考虑 undefined。空数组显式提供类型参数，表达期望的元素类型。

**动手试一试**：尝试给 count 调用 toUpperCase，阅读类型错误；再把 first 的参数改为 readonly T[]，观察还能否在函数内 push。

返回值变成 any 后，调用方无法获得元素类型约束，错误的方法调用可能直到运行时才暴露。
