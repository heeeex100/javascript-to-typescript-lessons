### 同一个工具，怎样记得你传的是哪种东西

想要一个取第一项的工具：传文字数组，希望拿到文字；传数字数组，希望拿到数字。不想为了两种输入各写一份完全相同的函数。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
const title = first(["JS", "TS"]);
const count = first([1, 2]);
const missing = first<number>([]);
console.log(title?.toUpperCase(), count, missing);
```

原例可在终端运行：`npm run concept -- 11`。

#### 2 · 一行一行看它做了什么

先读函数体：`return items[0]` 取第一项。空数组的第一项不存在，所以得到 undefined。这一点和 TS 无关，是数组真实的运行行为。

再读类型：`<T>` 可以先当作“给这次元素的类型临时起个名字”。items: T[] 表示一组这种类型的元素，返回 T | undefined 表示拿到一个这种元素，或者没有拿到。

first(["JS","TS"]) 这次 T 对应字符串；first([1,2]) 这次 T 对应数字。T 不是运行时装数据的变量，它是在表达输入和输出的联系。

title 可能没值，所以例子用 title?.toUpperCase()；有文字才转大写。missing 从空数组取值，输出 undefined。

#### 3 · 改一点，再看一次

先不改函数，只把第一个数组改成 ["hello"]，看输出变成大写 HELLO。

再给 count 调用 toUpperCase()。你拿到的是数字，编译器会指出这不是字符串方法；改回正确使用。

最后想象把返回类型全写 any：运行结果也许相同，但调用者写错方法时工具无法再提醒你。这就是“能运行”和“保留类型联系”的差别。

如果要保留自己的实验，先运行 `npm run concept -- 11 --prepare`，修改创建的文件，再用 `npm run concept -- 11 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

#### 4 · 分开练，先不做整道题

1. **先保留原来的类型**：用一个 T 把输入与输出连起来，不使用 any。
2. **空列表没有第一项**：把返回类型补完整，承认可能是 undefined。
3. **再给类型参数一个要求**：限制 T 至少带有 title: string，让函数可以读取标题。

网页下方有对应的小练习。每次只做一题：先运行起点 → 修改 → 检查 → 说清变化。做对以后换下一题，不需要先把整个主挑战写完。TS 小练习显示本地文件和命令，由真实编译器检查。

#### 5 · 做过之后，再认识这些名字

把这类“随输入确定的类型名字”称为**类型参数**，使用它的可复用工具叫**泛型**。

如果工具需要读取 title，就再声明 T 至少有 title:string。先做取第一项，再学约束，不需要一次读完复杂类型公式。

做完小练习后，回主挑战把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。
