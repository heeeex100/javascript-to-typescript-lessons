### 先拿到取件凭证，再等真正的结果

点外卖后立即拿到的是订单凭证，不是食物。函数也可能先给你一个 Promise，完成后才给出数据。下面的日志会显示调用开始、外部代码继续执行，以及结果返回的先后顺序。

#### 1 · 拿到凭证，再等结果

```js
async function loadLabel() {
  console.log("进入函数");
  await Promise.resolve();
  return "已完成";
}
console.log("开始");
const request = loadLabel();
console.log("继续主流程");
console.log(await request);
```

原例可在终端运行：`npm run concept -- 06`。

`console.log("开始")` 先输出。调用 loadLabel() 后，立即进入函数，所以打印“进入函数”。

遇到 await Promise.resolve()，本次函数先暂停后续部分，把执行机会交回外面。于是主流程打印“继续主流程”。注意：没有让整个程序原地卡住。

函数后来继续运行，return "已完成" 把这个值交给那次调用的 Promise。主流程的 await request 等到了它，所以最后打印“已完成”。

因此顺序是：开始 → 进入函数 → 继续主流程 → 已完成。request 不是最后那段文字；await request 得到的才是文字。


async 放在函数声明前，表示这个函数的调用结果是 Promise；它不会让每一行自动等待。await 写在要取得结果的表达式前，例如 `const label = await loadLabel()`，得到的才是最终文字。少写 await 时，label 会保存 Promise，可以打印 `typeof label` 或直接打印它，对比和文字的差别。

await 在普通函数体内不能直接使用，要把该函数声明为 async。本项目文件使用 ES 模块，所以文件最外层也允许 await；这不代表任意网页普通 script 里都能照搬顶层 await。async/await 是语法关键字，不能把自己的变量也命名为 await 来代替等待动作。

#### 2 · 两个结果再相加

只改函数里的等待：把 Promise.resolve() 换成 `new Promise(resolve => setTimeout(resolve, 500))`，感受最后一句晚一点出现。setTimeout 是安排稍后做一件事；resolve 在这里告诉 Promise“等待结束了”。

再把函数返回值改成一个数组。先打印 request，接着打印 await request，看两者区别。

失败也要等到取结果时处理：

```js
try {
  const value = await Promise.reject(new Error("离线"));
  console.log(value);
} catch (error) {
  console.log("稍后重试");
}
```

上面输出“稍后重试”。catch 提供失败路径，并没有把网络修好。


`new Promise(resolve => setTimeout(resolve, 500))` 可以分成三部分：new Promise 创建凭证；接收 resolve 的函数在创建时立即执行；setTimeout 安排稍后调用 resolve，成功完成这个 Promise。resolve 是这个参数在示例里的名字，不是你可以在任何地方直接使用的全局命令。

Promise.resolve(value) 给出会以这个值成功的 Promise，Promise.reject(reason) 给出被拒绝的 Promise；await 后者会把拒绝原因作为异常抛出，所以需要 catch 处理。

setTimeout 的 500 表示毫秒，约半秒；不是秒，也不保证恰好 500 毫秒准时执行。写 `setTimeout(resolve(), 500)` 会现在就调用 resolve，并把它的结果交给定时器，改变了等待顺序；这里应传函数本身。创建普通 Error 对象也使用 new，但 Number(text) 的转换不需要 new，不能把两种写法随意互换。

#### 3 · 给失败准备一句反馈

Promise 表示**将来的结果**。`async` 函数给调用方的总是 Promise；`await` 等成功结果，失败时则跳向能接住它的 catch。
