### 不知道传进来什么时，先问清楚再使用

一个函数可能收到文字，也可能收到 null 或数字。要求“未知输入都能安全处理”，就不能一上来调用 trim。先检查，再使用。

#### 1 · 先检查是不是文字

```ts
type ReadResult = { ok: true; value: number } | { ok: false; error: string };
function readCount(input: unknown): ReadResult {
  if (typeof input !== "number" || !Number.isFinite(input)) {
    return { ok: false, error: "需要有限数字" };
  }
  return { ok: true, value: input };
}
const result = readCount("3");
if (result.ok) console.log(result.value);
else console.log(result.error);
```

原例可在终端运行：`npm run concept -- 10`。

`input: unknown` 表示“任何东西都可能进来，目前还不确定”。不知道它是什么时，不能直接调用它的字符串方法。

例子先问 `typeof input !== "number"`：如果不是数字，就返回失败。`!Number.isFinite(input)` 还排除无效数字。只有这些判断都没挡住，后面才返回成功的数字。

返回结果有两种样子：成功有 ok:true 和 value；失败有 ok:false 和 error。不要把它们当成一个永远同时拥有两个字段的对象。

调用处先看 result.ok。成功分支读取 value，失败分支读取 error。例子传入 "3"，这是文字，所以打印“需要有限数字”。


`type ReadResult = ...` 为一个类型描述起别名，不是给运行时变量 ReadResult 存值。这里的 `|` 组合两种允许的类型，不是第 02 关的逻辑或 `||`，也不是要求对象同时具有两边的全部字段。

类型里的 `ok: true` 限定这一分支只能用 true；若写 `ok: boolean`，就可能是 true 或 false，会丢失这里用于区分结果的精确信息。类型里的 true、false、`"success"` 这类具体值要求，叫字面量类型。运行时的 `if (result.ok)` 则实际读取数据、选择分支，两层约定要一致。

#### 2 · 再按成功标记读字段

先把调用里的 "3" 改成数字 3，观察分支和输出变化。再试 null 和 NaN。

接着故意在判断 ok 之前读取 result.value，编译器会提醒：失败结果根本没有这个字段。恢复到先判断再读取。

综合大练习把这个做法换到标题文本：先问是不是字符串，再 trim，再问还剩不剩字。每一步只增加一个判断。

#### 3 · 最后拒绝空白标题

把“可能是什么”用检查逐渐确定下来，叫**类型收窄**。`A | B` 表示可能是 A，也可能是 B，叫**联合类型**。

ok:true / ok:false 是辨别这次结果属于哪种情况的标记。unknown 类型的值需要经过判断才能使用；any 会跳过许多类型检查。
