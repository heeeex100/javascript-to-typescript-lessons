### 从一次加法开始，最后自己写统计器

统计学习时长时，程序要记住已有总数，把符合条件的记录加进去。下面从 0 加到 3，再加到 8，接着把这个过程放进循环。

#### 1 · 先加一次，不写循环

先不写循环。想象账面上本来 0 元，收到 3 元后变为 3 元，又收到 5 元后变为 8 元。total 就是账面总数。

```js
let total = 0;
console.log("开始", total);
total = total + 3;
console.log("加了 3 后", total);
total = total + 5;
console.log("再加 5 后", total);
```

这段程序可以直接点“运行这个例子”。这一次先只盯住 `total = total + 3`：先读右边旧的 total=0，算出 0+3=3，再把 3 存回左边的 total。`=` 在这里是保存新值。

小练习先让你只做第一次加法。

#### 2 · 接着再加一次

本段完整例子如下，可以直接修改最后一次赋值做对比：

```js
let total = 0;
total = total + 3;
total = total + 5;
console.log(total);
```

正常输出 8。把第三行改成 total = 5，会输出 5，因为之前的 3 被覆盖了。

已有总数是 3，又来了 5。`total = 5` 是把旧总数直接换成 5；`total = total + 5` 才是在旧的 3 上加 5，得到 8。

| 这一步 | 旧的 total | 右边先计算 | 新的 total |
| --- | --- | --- | --- |
| 加 3 | 0 | 0 + 3 | 3 |
| 再加 5 | 3 | 3 + 5 | 8 |

所以代码中左右两个 total 的角色不同：右边先取旧值，左边再存新值。下一题故意把旧总数覆盖了，由你修好。

#### 3 · 让相同动作重复三次

数组 `[2,3,5]` 是按顺序放好的三个数。for...of 可以读成“每次拿一个数，叫 number，再做花括号里面的动作”。

```js
let total = 0;
for (const number of [2, 3, 5]) {
  total = total + number;
  console.log(number, total);
}
```

输出是 2 2、3 5、5 10。每次加法都用到了上一次留下的总数。total=0 放在循环前，只在开始执行一次。

如果把 `let total = 0` 移进循环，每次又会从 0 开始，输出就只剩 2、3、5。先自己把这两个版本对比运行一次，再做小题。

**把 for 这一行拆开读**

`for (const number of [2, 3, 5])`：括号圈出循环规则，of 右侧是要遍历的数据，左侧 const number 是本轮接收当前值的名字；花括号里的代码每拿到一项就执行一次。number 可以换名字，但循环体中的使用也要一起换。

这里的 const 不会阻止下一轮取得 3、5，因为每轮都有新的绑定。它限制的是这一轮内不能再写 `number = 99`。number 取得的是元素值，不是位置编号。`for...in` 主要用于遍历属性名，不是把 of 换个拼法，两者不能按同样含义使用。

这两种括号不能混换：`()` 是语法要求的循环头，`{}` 把需要重复的语句放在一起。少了配对的右括号或右花括号，通常会直接产生 SyntaxError。

#### 4 · 刚好等于也要算

“至少 25 分钟”包括刚好 25。`30 > 25` 是 true，但 `25 > 25` 是 false；`25 >= 25` 才是 true。

```js
console.log(25 > 25);
console.log(25 >= 25);
```

两次分别输出 false、true。这两个值表示“不符合”和“符合”。后面的 if 就用这个答案决定是否执行里面的代码。下一题先只问“这个数是否达标”，不把循环也放进来。

#### 5 · 加法只在条件成立时执行

现在把前面两件事组合起来：循环让每个数字都来看一次，if 决定这一个数字要不要加入总数。

```js
let total = 0;
for (const number of [2, 3, 5]) {
  if (number >= 3) {
    total = total + number;
  }
}
console.log(total);
```

2 不符合条件，跳过加法；3 和 5 符合，总数为 8。循环没有因为跳过 2 就结束，仍然继续看后面的数。

大题还需要数次数：达标时 count=count+1，未达标时可以在 else 里让 skipped=skipped+1。else 表示前面条件不成立时走的另一条路。

**if 后的括号、花括号能省吗？**

`if (number >= 3)` 中的小括号是这里必需的；花括号用来把多条语句归为同一组。不写花括号时，if 只控制紧跟着的那一条语句，缩进不会改变这个规则：

```js
const qualified = false;
let total = 0;
let count = 0;
if (qualified)
  total += 5;
  count += 1;
console.log(total, count);
```

虽然两行看起来缩进相同，输出仍是 0、1：count 那行不受 if 控制。给两行加上同一对花括号，再运行就会得到 0、0。

也不要写 `if (qualified);` 再接花括号。这个分号已经成为 if 控制的一条空语句，后面的块反而会正常执行。`if (...) { ... }` 的右花括号后通常不用再加分号。else 要接在对应的 if 块之后，中间不要插进其他语句；多个条件可以写 `else if`。

#### 6 · 换一组输入验证自己

最后再用新输入检验这套方法，不把答案写死。原来 [2,3,5] 的达标总数是 8，换成 [] 就应为 0，换成 [3,3] 就应为 6。

下面的小题已经提供函数外壳，这关只需把刚才的初始化、循环、条件放进去，最后返回 total；函数的完整用法在第 03 关继续学。

大题还要求平均时长：把达标总时长除以达标次数。`/` 是除法，例如 65/2 得到 32.5。没有达标记录时，次数是 0，这时不做除法，保留 average=0：

```js
const total = 65;
const count = 2;
let average = 0;
if (count > 0) average = total / count;
console.log(average);
```

`total += number` 只是 `total = total + number` 的简写。总数不断加入新值的做法常叫累加；total 保存的就是加到目前为止的总数。

#### 7 · “保存”与“比较”不是同一个动作

先看这三行，不急着把它们放进循环：

```js
const minutes = 25;
console.log(minutes === 25);
console.log(minutes === "25");
```

第一行的 `=` 把右边的数字保存到 minutes。第二行的 `===` 问“两边是不是同一种值”，得到 true。第三行一边是数字，一边是文字，得到 false。比较只给出答案，不会改掉 minutes。

`!==` 问“不相同吗”，例如 `25 !== "25"` 得到 true。`==` 会在一些情况下先转换类型，例如 `25 == "25"` 得到 true。先统一练 `===` 和 `!==`，需要转换就明确写 Number。

试一试：分别比较数字 0、文字 "0"、空文字 ""。先写下预计的真假，再运行。接下来的小题仍提供函数外壳，你只需写比较，完整函数用法在下一关学习。

#### 8 · 两项要求必须同时成立

报名规则是“满 18 岁，并且已经付款”。先把每一项要求变成一个真假答案，再用 `&&` 连起来：

```js
const age = 18;
const paid = false;
console.log(age >= 18);
console.log(paid === true);
console.log(age >= 18 && paid === true);
```

依次得到 true、false、false。年龄合格不够，还没有付款，所以最终拒绝。把 paid 改成 true，再把 age 改成 17，分别观察是哪一项拦住报名。

| 年龄合格 | 已付款 | 两项同时满足 |
| --- | --- | --- |
| true | true | true |
| true | false | false |
| false | true | false |
| false | false | false |

阅读时把 `&&` 读成“并且”。不要把多个业务要求挤成一串之后再猜含义。

#### 9 · 任意一项满足就可以

另一家体验馆的规则是“会员，或者有体验券”。会员没有券也能进，有券的非会员也能进。这次用 `||`：

```js
const member = false;
const ticket = true;
console.log(member || ticket);
console.log(member && ticket);
```

第一行比较得到 true，第二行得到 false。同一份数据，规则不同，结论不同。把两个变量分别换成 true/false，列出四种组合。

这里两边都是布尔值，所以得到布尔答案。更一般地，`&&` 和 `||` 会返回其中一个操作数：`0 || 10` 返回 10；`"已填写" || "缺省"` 返回“已填写”。它们还会短路，也就是左侧已经决定结果时不执行右侧。

```js
function showRight() { console.log("右边执行了"); return true; }
console.log(false && showRight());
console.log(true || showRight());
```

这两次都不会打印“右边执行了”。先把比较规则练熟，再用这个现象阅读代码。

#### 10 · “没有被禁用”怎样写

blocked 为 true 表示被禁用。报名需要“没有被禁用”，可以写 `!blocked`：

```js
const blocked = true;
console.log(blocked);
console.log(!blocked);
```

输出 true、false。`!` 把真假翻过来。于是完整规则可以按顺序读：年龄合格，并且已付款，并且没有被禁用。

如果同时出现 && 和 ||，先用括号把业务规则写明白。例如 `(member || ticket) && !blocked`，先确认会员或券，再排除禁用。不要依靠猜优先级理解报名规则。

#### 11 · 0 不代表没有填写

现在单独处理默认值。假设用户明确填了“奖励 0 分钟”，程序不应擅自补成 10：

```js
const bonus = 0;
console.log(bonus || 10);
console.log(bonus ?? 10);
```

输出 10、0。`||` 把 0 当作假，选择右边；`??` 只把 null 和 undefined 当作需要补默认值。它保留 0、false、空字符串。

条件中的 false、0、空字符串、null、undefined、NaN 会被当作假；空数组和空对象会被当作真。你可以逐个运行 `console.log(Boolean([]))`、`console.log(Boolean("false"))`、`console.log(Boolean(""))`，结果分别为 true、true、false。

“文字 false”仍是一段非空文字，不是布尔 false。是否允许空文字、是否允许 0，要由需求决定，不能只用“看起来有没有值”判断。

做完本题，再回到统计器综合题：每个达标判断都先得到一个布尔答案；没有达标记录时，要单独处理平均值，避免除以 0。

`??` 与 `||` 的区别来自它们的规则，不是问号比竖线“更安全”。想同时使用两种规则，需要写括号，例如 `(value ?? 0) || 10`；直接写 `value ?? 0 || 10` 会报语法错误。括号也把你想先算哪一步写明白了。第 09 关的 `?.` 又是另一种写法，作用是遇到 null 或 undefined 时停止访问。
