### 竞态条件、请求身份与过期结果

**竞态条件**指结果依赖多个操作实际发生的先后顺序。搜索 J 后再搜索 JS，并不保证 J 的响应先返回；晚完成的旧请求可能覆盖更新的意图。

- **await 的边界**：只保证本次调用中 await 后的语句等待本次结果；两个独立调用仍可能交错。
- **请求身份**：每次发起分配一个递增序号，并把本次序号保存在局部变量里。完成时与“最新发起序号”比较，才知道结果是否过期。
- **关键词不等于身份**：同一关键词也能连续请求两次，两次响应可能来自不同时间的数据；不能只比较文本。
- **所有终态都要判断**：旧请求的成功和失败都不该改掉新状态；catch 分支同样要遵守过期判断。
- **忽略不等于取消**：丢弃响应不会停止底层请求。防抖减少发起次数，取消尝试停止工作，两者也不能替代明确的最新结果规则。

<summary>读例子 → 改一个地方 → 检查理解</summary>

```js
let finishOld;
const oldRequest = new Promise(resolve => { finishOld = resolve; });
const oldView = oldRequest.then(value => console.log(value));
const newView = Promise.resolve("新结果").then(value => console.log(value));
await newView;
finishOld("旧结果");
await oldView;
```

**逐步理解**：刻意控制完成顺序，输出“新结果 → 旧结果”。如果两次 console.log 换成同一个页面的 render，旧内容就会最终留在页面。

**动手试一试**：在每次完成前记录“请求名、是否过期”。再把旧请求改为失败，思考错误提示能否也覆盖新页面。
