### 为什么看起来都是 20，加出来却不一样

页面输入框常常给你文字“20”。如果你想把它当分钟数继续计算，要用 Number 把它转成数字，否则 + 可能是在拼文字。

#### 1 · 先分清文字与数字

```js
const text = "8";
let total = Number(text);
total = total + 2;
console.log(text + 2, total);
console.log(typeof text, typeof total);
console.log(Number(""), Number("oops"));
```

原例可在终端运行：`npm run concept -- 01`。

`const text = "8"`：带着引号，存下的是文字。`Number(text)` 的意思是“试着把这段文字读成数字”，得到数字 8。原来的 text 仍是文字，不会自动改掉。

`let total = Number(text)` 让 total 先存数字 8。下一行 `total = total + 2` 的顺序是：先读右边旧的 total（8），算出 8+2（10），再把 10 放回左边的 total。

输出 `text + 2` 时，文字“8”后面接上“2”，所以是“82”；输出 total 时，那里存的是数字 10。

`typeof text` 会回答它是什么类型，这里回答 string，意思是文字。`typeof total` 回答 number，意思是数字。

最后一行让你看两个特殊结果：空文字转成 0；“oops”读不成数字，得到 NaN。不要把 NaN 理解成 0，它表示这次没拿到有效数字。

#### 2 · 再加五分钟

第一轮只把 text 从 "8" 改为 "10"，保留其他行。应看到“102”和 12。为什么不是两个 12？

第二轮改为 "abc"，观察 total。然后额外打印 `Number.isFinite(total)`：它会回答 false，告诉你这不是可用的有限数字。

最后把 `let total` 暂时改为 `const total`。程序在重新给 total 赋值时会报错：const 不允许更换它存的值。恢复 let 后继续。


**为什么有时写 let，有时只写变量名？**

`let total = 8` 创建 total 并给它初始值；`total = 10` 给已有的 total 换值，不再声明。若在同一块范围里又写一次 `let total = 10`，会因重复声明报错。名字在声明前也不能随意使用，例如把 `console.log(total)` 移到 let 前面会报 ReferenceError。

`let total;` 没有初始值时，total 是 undefined；`const total;` 则不合法，因为 const 声明时就必须给初始值。undefined 表示这里还没有提供值，不是文字 `"undefined"`。null 通常用来明确表示“这里是空的”，也不是文字 `"null"`。

```js
let value;
console.log(value, typeof value);
value = null;
console.log(value === null);
```

第一行输出 undefined 和字符串 undefined，第二行输出 true。输出区看起来相似的内容，真实类型可能不同。

#### 3 · 识别转不成数字的输入

**类型**就是区分“数字、文字、真假”等不同的值。**转换**是 Number(text) 这样的实际操作。

需要重新赋值时使用 let；只在开始存一次、不再换值时使用 const。先选 const，需要更换再选 let。输入是不是空文本、是否允许负数，还要按实际要求另外判断。


**算式也有先后顺序**

`2 + 3 * 4` 是 14，`(2 + 3) * 4` 是 20。这里的括号让加法先算，与 console.log 后面用于调用的括号用途不同。`/` 是除法，`%` 取余数，例如 `7 % 3` 是 1；`**` 求幂，例如 `2 ** 3` 是 8。

JS 的普通整数和小数都属于 number，例如 `typeof 3`、`typeof 3.5` 都是 `"number"`。`NaN` 也是 number 类型的特殊值，不能用 `value === NaN` 判断它；需要判断是不是 NaN 时用 Number.isNaN，需要有限数字时用 Number.isFinite。普通小数计算也可能有误差，例如 0.1 + 0.2 不严格等于 0.3；这不代表加法语法写错了。

试着打印 `(2 + 3) * 4` 与 `2 + 3 * 4`，再比较 `"2" + 3 + 4` 和 `2 + 3 + "4"`：后两者分别得到文字 234 和 54，都是逐步计算，只是在不同位置遇到了字符串。
