### 从读取一张卡到保留旧数据的编辑

一项任务有标题和完成状态，可以放进一个对象；多项任务放进数组。

#### 1 · 先读一个对象的属性

```js
const book = { title: "JS", read: false };
console.log(book.title);
const books = [book, { title: "TS", read: true }];
console.log(books[0].title);
```

原例可在终端运行：`npm run concept -- 04`。

`{ title: "JS", read: false }` 表示一张卡：title 这栏写着 JS，read 这栏写着 false，表示没读过。

`book.title` 先找到 book 这张卡，再取 title 这一栏，所以得到文字 JS。

books 的方括号把两张卡按顺序放成一组。`books[0]` 取第一张；位置从 0 开始，所以第二张是 books[1]。`books[0].title` 先取第一张，再取它的标题，仍是 JS。

下一步才是遍历。你已经在第 02 关学过 for...of：每次取一张卡，看看 read 是否为 false，需要时取它的 title。


<details>
<summary>补充：这里的花括号、方括号和冒号</summary>

`{ title: "JS", read: false }` 中，花括号创建对象，冒号左侧是字段名，右侧是字段值；逗号分隔字段，不用分号。`title` 这类名称可以不加引号，含空格的字段名则要加，例如 `{ "book title": "JS" }`，读取时写 `book["book title"]`。写 `book.title` 时 title 是固定名称，不会读取某个叫 title 的变量。

`[book, anotherBook]` 的方括号创建数组，逗号分开各个元素；`books[0]` 的方括号则是在读取已有数组的第 0 项。位置从 0 开始，长度为 2 的数组有效位置是 0、1，`books[2]` 得到 undefined。再对这个 undefined 取 .title 就会报错，不会自动得到一张空卡。

JS 对象和数组最后一项后面可以保留一个逗号，称为尾逗号，通常方便以后加新项。但 `[1, , 3]` 中间空一项会产生数组空位，不是无意义的排版；第 05 关的 JSON 格式也不允许尾逗号。

books.length 读取数组的元素个数，是属性，不是函数，所以不用再接 ()。有两项时 length 为 2，但最后一项的下标是 1。空数组 length 为 0，不能用 length 本身当作最后一项的位置。

#### 2 · 先筛选，不转换

先练 filter：

```js
const books = [{ title: "JS", read: false }, { title: "TS", read: true }];
const unread = books.filter(book => !book.read);
console.log(unread);
```

filter 每次把一张卡交给你写的函数。你交回 true，就留下这张；交回 false，就跳过。`!false` 是 true，所以 !book.read 留下没读过的卡。先观察结果是对象数组，还不是文字数组。

再单独加一行 `const titles = unread.map(book => book.title)`。map 问的是“这一项要换成什么”，这里回答标题，所以得到 ["JS"]。它不是再筛选一次。

最后体验一个坑：`const copy = books` 只是给同一组卡多起一个名字。改 copy[0].read，books[0].read 也会变。`[...books]` 只复制放卡的列表，卡本身仍共享；需要更改卡又保留旧卡时，用 `{ ...book, read: true }` 创建另一张卡。

#### 3 · 再把对象换成标题

这次只做转换，保留每一项，但取出它的标题：

```js
const books = [{ title: "JS", read: false }, { title: "TS", read: true }];
const titles = books.map(book => book.title);
console.log(titles);
console.log(books.length, titles.length);
```

输出 ["JS","TS"] 和 2、2。map 的结果变成文字数组；原 books 仍是两张对象卡片。

一张带属性的数据叫**对象**，有顺序的一组数据叫**数组**。交给 filter/map、让它们逐项调用的函数叫**回调函数**。

“两个名字指向同一张卡”的关系叫共享**引用**。给其中一个名字下的对象改字段，另一个名字读到的值也会变。


`books.filter(...)` 是调用数组提供的 filter 方法。点号是从这个数组取得方法，括号里传入的回调才说明保留条件。`filter` 回调要交回真假答案，`map` 回调交回要放入新数组的值，两者都不是“把里面的代码写上去就会自动猜结果”。

写成 `books.filter(book => !book.read).map(book => book.title)` 时，后面的 map 作用于 filter 返回的新数组，不是回到原始 books 上重做。把它拆成 unread、titles 两个变量，行为相同，但能打印中间结果。read、title、filter 这些名字都区分大小写。

#### 4 · 字段名也可以来自输入

```js
const task = { title: "复习", done: false };
const key = "title";
console.log(task.title);
console.log(task[key]);
console.log(task.key);
```

输出“复习”“复习”、undefined。点号后写 title，就是找名称为 title 的字段。方括号里写变量 key，则先取 key 保存的文字，再按这个名称查找字段。task.key 找的是名为 key 的字段，这张卡没有它。

把 key 改成 "done"，不改 task[key]，输出就变成 false。再换成 "missing"，观察不存在的属性得到 undefined。这是按不同字段读取数据的基础。

#### 5 · 解构只是换一种取字段的写法

```js
const task = { title: "复习", done: false };
const { title, done } = task;
console.log(title, done);
console.log(task.title);
```

第二行可以展开成两行：`const title = task.title` 和 `const done = task.done`。左边的花括号指定要取出的字段，右边是来源。不是把 task 变成另一种数据，也没有删除它的字段。

只取 title 时可以写 `const { title } = task`。数组也能按位置取出：`const [first, second] = [10, 20]`，两个变量分别得到 10、20。先能用原来的点号或下标写出来，再采用这种简写。

如果取出的字段本身也是对象，仍然可能和原数据共享；“取出来”不等于“复制整个对象”。

同样的花括号放在不同位置，作用会变：`const { title } = task` 是从已有对象取值，`const copy = { title }` 是用变量 title 的当前值创建新对象，后者等价于 `{ title: title }`。

如果不想让变量与字段同名，可写 `const { title: bookTitle } = task`：取的是 title 字段，创建的变量叫 bookTitle，不会另外声明 title。这里的冒号是在改取值后的变量名，不是下一阶段 TS 的类型注解。

#### 6 · 起两个名字，不会自动得到两张卡

```js
const before = { title: "复习", done: false };
const alias = before;
alias.done = true;
console.log(before.done);
```

输出 true。before 和 alias 都指向同一张卡。用 const 只是不能让这个变量改指向另一张卡，不会把卡片字段锁住。

现在重新运行另一个版本：

```js
const before = { title: "复习", done: false };
const after = { ...before, done: true };
console.log(before.done, after.done);
console.log(before === after);
```

输出 false、true，最后是 false。这次花括号创建了新对象，...before 把旧字段放进去，后面的 done 覆盖新卡片里的那一项。对比 `{ done: true, ...before }`，后面的旧 done 又会覆盖 true；顺序有意义。

`...` 的意思也要看位置。`{ ...task }` 把字段展开到新对象；`[...books]` 把元素展开到新数组；`cost(...[7, 3])` 把数组元素分别当作调用参数，相当于 cost(7,3)。下面这个相反方向的用法，把传入的多个参数收成数组：

```js
function collect(...values) { return values; }
console.log(collect(2, 3, 5));
```

输出 [2,3,5]。参数位置的 ...values 叫剩余参数，必须放在参数列表最后。省掉 ... 就变成只接收第一个参数，不会自动收齐后面的值。

#### 7 · 复制外层，里面的卡片仍可能共用

```js
const before = { title: "复习", meta: { minutes: 20 } };
const after = { ...before };
after.meta.minutes = 30;
console.log(before.meta.minutes);
console.log(before.meta === after.meta);
```

输出 30、true。外层对象不同，但它们的 meta 仍指向同一个对象。展开只复制当前这一层，这种复制叫**浅拷贝**。

如果要改 meta.minutes，又保留旧数据，就要在要修改的路径上逐层创建新对象：外层一份、meta 再一份。并不是所有层都必须复制，而是不能继续修改共享的那部分。

试着画两个外层盒子，各用一根箭头指向同一个 meta；再画出独立的新 meta。下面的小题会用旧数据是否保持不变来检查，不能只看新结果的数字对不对。

#### 8 · 改一项任务，要照顾数组和对象两层

```js
function rename(tasks, id, title) {
  return tasks.map(task => {
    if (task.id === id) {
      return { ...task, title: title };
    }
    return task;
  });
}
const before = [{ id: 1, title: "A" }, { id: 2, title: "B" }];
const after = rename(before, 1, "C");
console.log(before[0].title, after[0].title);
```

输出 A、C。map 创建新数组；匹配的任务返回新对象，不匹配的任务保留原对象。找不到 id 时，每一项都原样保留。

`task => task.id === id ? 新值 : 旧值` 是同样判断的简写，问号前是条件，冒号分隔两种结果。先用上面的 if 版本写明白，不要求一次学会简写。

注意：map 本身不会替你复制每个对象。如果回调里直接写 `task.title = title`，仍会改旧卡片。最后的综合任务既检查新列表，也检查旧列表，帮你发现这种问题。
