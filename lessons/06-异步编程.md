## 一步一步看懂，再拆开练

### 先拿到取件凭证，再等真正的结果

点外卖后立即拿到的是订单凭证，不是食物。函数也可能先给你一个 Promise，之后才交付真正数据。先盯住下面四行日志的顺序。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```js
async function loadLabel() {
  console.log("进入函数");
  await Promise.resolve();
  return "已完成";
}
console.log("开始");
const request = loadLabel();
console.log("继续主流程");
console.log(await request);
```

原例可在终端运行：`npm run concept -- 06`。

#### 2 · 一行一行看它做了什么

`console.log("开始")` 先输出。调用 loadLabel() 后，立即进入函数，所以打印“进入函数”。

遇到 await Promise.resolve()，本次函数先暂停后续部分，把执行机会交回外面。于是主流程打印“继续主流程”。注意：没有让整个程序原地卡住。

函数后来继续运行，return "已完成" 把这个值交给那次调用的 Promise。主流程的 await request 等到了它，所以最后打印“已完成”。

因此顺序是：开始 → 进入函数 → 继续主流程 → 已完成。request 不是最后那段文字；await request 得到的才是文字。

#### 3 · 改一点，再看一次

只改函数里的等待：把 Promise.resolve() 换成 `new Promise(resolve => setTimeout(resolve, 500))`，感受最后一句晚一点出现。setTimeout 是安排稍后做一件事；resolve 在这里告诉 Promise“等待结束了”。

再把函数返回值改成一个数组。先打印 request，接着打印 await request，看两者区别。

失败也要等到取结果时处理：

```js
try {
  const value = await Promise.reject(new Error("离线"));
  console.log(value);
} catch (error) {
  console.log("稍后重试");
}
```

上面输出“稍后重试”。catch 提供失败路径，并没有把网络修好。

如果要保留自己的实验，先运行 `npm run concept -- 06 --prepare`，修改创建的文件，再用 `npm run concept -- 06 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

#### 4 · 分开练，先不做整道题

1. **拿到凭证，再等结果**：request 是 Promise。让 value 真正成为数字 7。
2. **两个结果再相加**：先等到两个数字，再相加得到 9。
3. **给失败准备一句反馈**：请求失败时，把 message 设为“稍后重试”。

网页下方有对应的小练习。每次只做一题：先运行起点 → 修改 → 检查 → 说清变化。做对以后换下一题，不需要先把整个主挑战写完。TS 小练习显示本地文件和命令，由真实编译器检查。

#### 5 · 做过之后，再认识这些名字

Promise 表示**将来的结果**。`async` 函数给调用方的总是 Promise；`await` 等成功结果，失败时则跳向能接住它的 catch。

先会画出这一条调用的先后，再去第 15 关研究“同时发出两次请求，谁先结束”。这两件事不要一起硬背。

做完小练习后，回主挑战把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。

### 06-02 · 两个结果再相加

先等到两个数字，再相加得到 9。

```js
const a = Promise.resolve(4);
const b = Promise.resolve(5);
const total = 0;
```

在实验台选择这道小题，或运行 `npm run drill -- 06-02 --prepare` 后编辑 `practice/steps/06-02.js`，再运行 `npm run drill -- 06-02 --check`。

<details>
<summary>一点提示</summary>

(await a) 的结果是 4，(await b) 的结果是 5。

</details>

<details>
<summary>试过后再看解释</summary>

```js
const a = Promise.resolve(4);
const b = Promise.resolve(5);
const total = (await a) + (await b);
```

等待语法可以出现在表达式中，算术仍然需要真实数字。

</details>

### 06-03 · 给失败准备一句反馈

请求失败时，把 message 设为“稍后重试”。

```js
let message = "";
try {
  await Promise.reject(new Error("离线"));
} catch {
  // 在这里补上反馈
}
```

在实验台选择这道小题，或运行 `npm run drill -- 06-03 --prepare` 后编辑 `practice/steps/06-03.js`，再运行 `npm run drill -- 06-03 --check`。

<details>
<summary>一点提示</summary>

这题不用修好网络，只需在失败路径更新文字。

</details>

<details>
<summary>试过后再看解释</summary>

```js
let message = "";
try {
  await Promise.reject(new Error("离线"));
} catch {
  message = "稍后重试";
}
```

await 遇到失败会跳到 catch；成功路径之后的代码不会替你处理失败。

</details>
