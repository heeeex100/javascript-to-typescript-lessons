### 为什么看起来都是 20，加出来却不一样

页面输入框常常给你文字“20”。如果你想把它当分钟数继续计算，要先把这段文字变成数字。先运行例子，再看哪一步发生了变化。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```js
const text = "8";
let total = Number(text);
total = total + 2;
console.log(text + 2, total);
console.log(typeof text, typeof total);
console.log(Number(""), Number("oops"));
```

原例可在终端运行：`npm run concept -- 01`。

#### 2 · 一行一行看它做了什么

`const text = "8"`：带着引号，存下的是文字。`Number(text)` 的意思是“试着把这段文字读成数字”，得到数字 8。原来的 text 仍是文字，不会自动改掉。

`let total = Number(text)` 让 total 先存数字 8。下一行 `total = total + 2` 的顺序是：先读右边旧的 total（8），算出 8+2（10），再把 10 放回左边的 total。

输出 `text + 2` 时，文字“8”后面接上“2”，所以是“82”；输出 total 时，那里存的是数字 10。

`typeof text` 会回答它是什么类型，这里回答 string，意思是文字。`typeof total` 回答 number，意思是数字。

最后一行让你看两个特殊结果：空文字转成 0；“oops”读不成数字，得到 NaN。不要把 NaN 理解成 0，它表示这次没拿到有效数字。

#### 3 · 改一点，再看一次

第一轮只把 text 从 "8" 改为 "10"，保留其他行。应看到“102”和 12。为什么不是两个 12？

第二轮改为 "abc"，观察 total。然后额外打印 `Number.isFinite(total)`：它会回答 false，告诉你这不是可用的有限数字。

最后把 `let total` 暂时改为 `const total`。程序在重新给 total 赋值时会报错：const 不允许更换它存的值。恢复 let 后继续。

如果要保留自己的实验，先运行 `npm run concept -- 01 --prepare`，修改创建的文件，再用 `npm run concept -- 01 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

1. **先分清文字与数字**：不改 input，把 numeric 变为数字 20。

#### 5 · 做过之后，再认识这些名字

**类型**就是区分“数字、文字、真假”等不同的值。**转换**是 Number(text) 这样的实际操作。

需要重新赋值时使用 let；只在开始存一次、不再换值时使用 const。先选 const，需要更换再选 let。输入是不是空文本、是否允许负数，还要按实际要求另外判断。

### 01-03 · 识别转不成数字的输入

实现 isUsable，让 0 和 20 得到 true，NaN 和 Infinity 得到 false。

```js
function isUsable(value) { return typeof value === "number"; }
```

在实验台选择这道小题，或运行 `npm run drill -- 01-03 --prepare` 后编辑 `practice/steps/01-03.js`，再运行 `npm run drill -- 01-03 --check`。

<details>
<summary>一点提示</summary>

</details>

<details>
<summary>试过后再看解释</summary>

```js
function isUsable(value) { return Number.isFinite(value); }
```

typeof NaN 仍是 number；只问类型不足以确定能否正常计时。

</details>

## 刚才发生了什么

输入框和引号里的“20”是字符串。+ 在这里做了拼接。Number(input) 才产生可计算的数字。typeof 帮你看到区别。空文本转为 0、错误文本转为 NaN，所以转换与校验是两件事。
