## 边看边练

### 同一个工具，怎样记得你传的是哪种东西

想要一个取第一项的工具：传文字数组，希望拿到文字；传数字数组，希望拿到数字。不想为了两种输入各写一份完全相同的函数。

#### 1 · 先保留原来的类型

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
const title = first(["JS", "TS"]);
const count = first([1, 2]);
const missing = first<number>([]);
console.log(title?.toUpperCase(), count, missing);
```

原例可在终端运行：`npm run concept -- 11`。

先读函数体：`return items[0]` 取第一项。空数组的第一项不存在，所以得到 undefined。这一点和 TS 无关，是数组真实的运行行为。

再读类型：`<T>` 可以先当作“给这次元素的类型临时起个名字”。items: T[] 表示一组这种类型的元素，返回 T | undefined 表示拿到一个这种元素，或者没有拿到。

first(["JS","TS"]) 这次 T 对应字符串；first([1,2]) 这次 T 对应数字。T 不是运行时装数据的变量，它是在表达输入和输出的联系。

title 可能没值，所以例子用 title?.toUpperCase()；有文字才转大写。missing 从空数组取值，输出 undefined。


##### 就地小练习 11-01 · 先保留原来的类型

用一个 T 把输入与输出连起来，不使用 any。

```ts
function same<T>(value: T): string { return "固定文字"; }
```

网页中在这一段下面直接练习。本地运行 `npm run drill -- 11-01 --prepare`，编辑 `practice/steps/11-01.ts`，再运行 `npm run drill -- 11-01 --check`。

<details>


#### 2 · 空列表没有第一项

先不改函数，只把第一个数组改成 ["hello"]，看输出变成大写 HELLO。

再给 count 调用 toUpperCase()。你拿到的是数字，编译器会指出这不是字符串方法；改回正确使用。

最后想象把返回类型全写 any：运行结果也许相同，但调用者写错方法时工具无法再提醒你。这就是“能运行”和“保留类型联系”的差别。

如果要保留自己的实验，先运行 `npm run concept -- 11 --prepare`，修改创建的文件，再用 `npm run concept -- 11 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。


##### 就地小练习 11-02 · 空列表没有第一项

把返回类型补完整，承认可能是 undefined。

```ts
function first<T>(items: T[]): T { return items.length ? items[0]! : undefined; }
```

网页中在这一段下面直接练习。本地运行 `npm run drill -- 11-02 --prepare`，编辑 `practice/steps/11-02.ts`，再运行 `npm run drill -- 11-02 --check`。

<details>
<summary>一点提示</summary>

返回值可能是两种类型，用 | 连接。

</details>

<details>
<summary>试过后再看解释</summary>

```ts
function first<T>(items: T[]): T | undefined { return items.length ? items[0]! : undefined; }
```

类型签名应该把可能没结果这件事告诉调用者。

</details>

#### 3 · 再给类型参数一个要求

把这类“随输入确定的类型名字”称为**类型参数**，使用它的可复用工具叫**泛型**。

如果工具需要读取 title，就再声明 T 至少有 title:string。先做取第一项，再学约束，不需要一次读完复杂类型公式。

做完小练习后，回综合大练习把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。


##### 就地小练习 11-03 · 再给类型参数一个要求

限制 T 至少带有 title: string，让函数可以读取标题。

```ts
function titleOf<T>(item: T): string { return item.title; }
```

网页中在这一段下面直接练习。本地运行 `npm run drill -- 11-03 --prepare`，编辑 `practice/steps/11-03.ts`，再运行 `npm run drill -- 11-03 --check`。

<details>
<summary>一点提示</summary>

extends { title: string } 写在 T 后面。

</details>

<details>
<summary>试过后再看解释</summary>

```ts
function titleOf<T extends {title: string}>(item: T): string { return item.title; }
```

约束告诉编译器：并非任意类型，只收具有这个属性的类型。

</details>

## 综合大练习：保留输入类型的查找工具箱

**完成两个泛型工具，既处理缺失结果，也把对象的具体类型交回调用方。**

### 完成要求

- first<T>(items:readonly T[]):T|undefined 返回第一项；空列表返回 undefined。
- findById<T extends {id:number}>(items:readonly T[],id:number):T|undefined 按 id 查找。
- 不修改输入，返回值保留原元素的具体类型与字段；找不到时返回 undefined。

### 输入与预期结果

first([3,4]) → 3；first([]) → undefined；查任务得到带 title 的任务，查用户得到带 name 的用户。
