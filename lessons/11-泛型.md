## 边看边练

### 同一个工具，怎样记得你传的是哪种东西

想要一个取第一项的工具：传文字数组，希望拿到文字；传数字数组，希望拿到数字。不想为了两种输入各写一份完全相同的函数。

#### 1 · 先保留原来的类型

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
const title = first(["JS", "TS"]);
const count = first([1, 2]);
const missing = first<number>([]);
console.log(title?.toUpperCase(), count, missing);
```

原例可在终端运行：`npm run concept -- 11`。

先读函数体：`return items[0]` 取第一项。空数组的第一项不存在，所以得到 undefined。这一点和 TS 无关，是数组真实的运行行为。

再读类型：`<T>` 可以先当作“给这次元素的类型临时起个名字”。items: T[] 表示一组这种类型的元素，返回 T | undefined 表示拿到一个这种元素，或者没有拿到。

first(["JS","TS"]) 这次 T 对应字符串；first([1,2]) 这次 T 对应数字。T 不是运行时装数据的变量，它是在表达输入和输出的联系。

title 可能没值，所以例子用 title?.toUpperCase()；有文字才转大写。missing 从空数组取值，输出 undefined。


`function first<T>` 的尖括号声明类型参数，不是拿 T 去做大小比较。T 是习惯名称，可以改成 Item，但同一函数签名里要一起改。`items: T[]` 中的方括号表示数组类型；`items[0]` 的方括号读取实际数据，它们不在同一层做事。

调用 `first([1,2])` 时 TS 通常能从数组推断 T；`first<number>([])` 则明确告诉它空数组打算放哪种元素。调用处的 `<number>` 只提供类型，不会给空数组塞进一个 0，也不会让不存在的第一项变成数字。

#### 2 · 空列表没有第一项

用同一个函数比较有元素和空数组：

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}
console.log(first(["JS"]));
console.log(first<string>([]));
```

分别输出 JS、undefined。返回约定需要包含第二种情况。下面小题的非空断言 ! 会掩盖这个事实，需要修正返回类型。

先把第一处调用改成 first(["hello"])，输出变成 hello；再改成 first([42])，输出变成数字 42。空数组那次调用仍得到 undefined，和另一处传了什么元素无关。

最后想象把返回类型全写 any：运行结果也许相同，但调用者写错方法时工具无法再提醒你。这就是“能运行”和“保留类型联系”的差别。


你会在小题里看到 `items[0]!`。值后面的 ! 是 TS 的非空断言，告诉检查器“我认为这里不是 null/undefined”，不会在运行时检查或补值。第 02 关的 `!blocked` 则是在值前面做逻辑取反，真的计算一个布尔值，两者不能混用。

如果数组可能为空，返回类型仍应包括 undefined，或者先用实际分支处理空数组。给读取表达式加 ! 不会解决数据不存在的问题。本关起点中的这个写法正是要你检查返回约定，而不是靠断言掩盖空数组。

##### 就地小练习 11-02 · 空列表没有第一项

把返回类型补完整，承认可能是 undefined。

```ts
function first<T>(items: T[]): T { return items.length ? items[0]! : undefined; }
```

#### 3 · 再给类型参数一个要求

需要读取 title 时，先声明这个字段必须存在：

```ts
function titleOf<T extends { title: string }>(item: T): string {
  return item.title;
}
console.log(titleOf({ title: "JS", done: false }));
// titleOf({ done: false });
```

输出 JS。额外的 done 字段可以保留；取消最后一行注释，缺少 title 会被检查出来。

把这类“随输入确定的类型名字”称为**类型参数**，使用它的可复用工具叫**泛型**。

如果工具需要读取 title，就再声明 T 至少有 title:string。例如 `<T extends { title: string }>` 要求传入的数据含有文字类型的 title；这样函数体才能读取它。


`<T extends { title: string }>` 的 extends 要求 T 的结构至少符合右侧形状。它仍保留 T 的其他信息，例如多一个 done 字段仍可传入；并不是把对象裁剪到只剩 title，也不是运行时执行继承操作。拿掉约束后，在函数体直接读取任意 T 的 .title 就没有依据，编译器会拒绝。

综合题按 id 查找时可以用 items.find(item => item.id === id)。find 与 filter 都调用判断函数，但 find 返回第一项匹配的对象，找不到返回 undefined；filter 返回所有匹配项组成的数组。把 find 的结果当数组再 .map，或者把 filter 的空数组当作 undefined，都会弄错返回约定。T extends {id:number} 的约束让这个查找回调能够读取 id，同时保留找到那项的其他字段类型。

##### 就地小练习 11-03 · 再给类型参数一个要求

限制 T 至少带有 title: string，让函数可以读取标题。

```ts
function titleOf<T>(item: T): string { return item.title; }
```
