### 从存档文本到跨文件工具与断点调试

文件里写着 [1,2]，不等于程序已经拿到了数组。先把“文本读成值”做成功，再故意读坏文本，最后才加保护。

#### 1 · 先认识正常 JSON

```js
const saved = JSON.stringify({ title: "复习" });
console.log(typeof saved);
const task = JSON.parse(saved);
console.log(task.title);
```

原例可在终端运行：`npm run concept -- 05`。

第一行把任务对象转换成适合保存的文字。第二行输出 string，说明 saved 中放的是文本。你可以额外 console.log(saved)，会看到带双引号的字段内容。

第三行 JSON.parse(saved) 读这段文本，得到真正的对象。第四行才可以使用 task.title，输出“复习”。

把 saved 的来源换成 "oops" 再解析，解析器会报错，因为它不符合 JSON 的格式。如果不处理，当前这段程序会在这里停下，后面的正常流程继续不了。


**JS 对象和 JSON 文本长得像，但写法不完全相同**

JS 可以写 `{ title: '复习' }`；对应 JSON 内容要求字段名和字符串都使用双引号：`{"title":"复习"}`。如果把它放在 JS 字符串里，外面可以用单引号包住，例如 `' {"title":"复习"} '`，外层引号是 JS 语法，不是 JSON 数据的一部分。

JSON 不允许注释和尾逗号，也不能把函数或 undefined 当作 JSON 值。可以对比 `JSON.parse('{"title":"复习"}')` 和 `JSON.parse('{"title":"复习",}')`：后者会抛 SyntaxError，不是因为标题内容有问题，而是文本格式不合法。

#### 2 · 先只处理格式坏掉

先只接住格式错误：

```js
try {
  const value = JSON.parse("oops");
  console.log(value);
} catch {
  console.log("存档格式坏了");
}
```

try 里正常运行时，catch 不会执行。try 里抛错时，跳到 catch，这里就有机会给用户反馈或选默认值。

然后把 "oops" 改成 "123"：这次没有报错，因为 123 是合法 JSON。可它不是任务列表！所以要再用 Array.isArray(value) 问“读出来的是数组吗”。一次检查格式，一次检查内容结构。

模块不用和 JSON 混着记：一个文件 export 一个函数，另一个文件 import 它，就是把写好的工具交给另一份文件使用。本关先完成存档保护，再打开 examples/js/05-modules.js 对照两个文件。


try 和 catch 各自后面的花括号都必须写。`catch (error) { ... }` 把这次抛出的内容绑定为 error，供你读取；不需要这个内容时可写 `catch { ... }`，两者都能接住异常。error 只在这个 catch 范围内可用。

`throw new Error("分钟无效")` 中，new Error 创建一个错误对象，throw 才将它抛出并打断当前正常路径。只写 `new Error(...)` 会得到对象，不会自动进入 catch。catch 处理结束后，还可以继续执行整个 try/catch 之后的代码；不会回到 try 中报错那行的下一行重新接着跑。

```js
try {
  console.log("检查前");
  throw new Error("分钟无效");
  console.log("检查后");
} catch (error) {
  console.log(error.message);
}
console.log("结束");
```

依次输出“检查前”“分钟无效”“结束”，“检查后”不会出现。

#### 5 · 自己写的函数，也能交给另一份文件

上一题借用别人提供的工具，这次反过来。运行 `npm run drill -- 05-05 --prepare`。main.js 是你要写的工具，consumer.js 是使用者：

```mjs
// consumer.js
import { double } from "./main.js";
export function evaluate(value) {
  return double(value);
}
```

要让这段代码工作，main.js 必须提供名称为 double 的**具名导出**：函数声明前加 export。名称拼错或忘记导出，使用者就拿不到工具。

试着去掉 export，检查会报“没有导出 double”；补回 export 后，再换几个数字调用。这里的 `export function double` 对应另一份文件中的 `import { double }`。默认导出使用另一套写法。

模块的作用是分清每份文件负责什么。综合存档工具完成后，可以把保存与读取函数移到 storage.js，再让 main.js 导入它们，走一遍“保存 → 读取 → 打印”的完整流程。

`import { double }` 的花括号在选择具名导出，不是在这里新建对象；它也不是第 04 关的变量解构语句。需要换当前文件里的名字时可写 `import { double as twice } from "./main.js"`，之后调用 twice；原模块仍导出 double。

另一种配对是 `export default function double(...) { ... }` 与 `import twice from "./main.js"`。默认导入不加花括号，本地名字可以自己取；具名导入要对应导出名，或显式用 as 改名。本关练习要求具名导出，改成 default 后，原来的 `import { double }` 不会因此继续有效。

#### 6 · 先复现，再判断哪一行失败

下面三个输入会遇到不同的问题。把 text 分别改成 "oops"、"null"、"{}" 运行：

```js
const text = "null";
try {
  const value = JSON.parse(text);
  console.log("解析出来", value);
  console.log(value.length);
} catch (error) {
  console.log(error.name, error.message);
}
```

"oops" 在 JSON.parse 就失败，属于文本语法问题。"null" 解析成功，日志先显示 null，再在读取 length 时出现 TypeError。"{}" 不抛错，但 length 是 undefined，也不符合“返回数量”的要求。

所以至少有三种情况：写法或文本无法解析、对当前值做不了这个操作、能运行但结果不符合需求。报错时先读错误名称和消息，再找文件与行号。错误堆栈通常还列出谁调用了这个函数；先找属于自己代码的位置。

本地检查会附加验收代码，超出自己源码的行号可能来自验收。回到提示对应的输入复现，观察真实值，再决定补格式保护还是结构检查。

##### 就地小练习 05-06 · 先看失败发生在哪一步

loadCount 接受 JSON 数组文本。坏文本、null 或对象均返回 0；不要在检查前读取 length。

```js
function loadCount(text) {
  const value = JSON.parse(text);
  return value.length;
}
```

网页中在这一段下面直接练习。本地运行 `npm run drill -- 05-06 --prepare`，编辑 `practice/steps/05-06.js`，再运行 `npm run drill -- 05-06 --check`。

<details>
<summary>一点提示</summary>

先分别运行三个坏输入。JSON.parse 抛错与拿到 null 后访问属性，是不同失败位置。

</details>

<details>
<summary>参考答案与解释</summary>

```js

  try {
    const value = JSON.parse(text);
    if (!Array.isArray(value)) return 0;
    return value.length;
  } catch { return 0; }
}
```

修复顺序：复现输入，定位失败行，确认当时的值，再加对应的保护。不能只修眼前一种输入。

</details>

#### 7 · 能运行，数字也可能已经算错

一笔订单：2 件、每件 12 元、优惠 3 元。先写出中间结果：小计 24，实付 21。再运行有问题的版本：

```js
const quantity = 2;
const price = 12;
const subtotal = quantity + price;
console.log("小计", subtotal);
const total = subtotal - 3;
console.log("实付", total);
```

它能执行完，但小计首先就变成了 14，后面自然得到 11。应该修 subtotal 那一行，而不是在最终结果上补 10。

排查顺序：写一组能复现的数据；列出预期的中间值；逐步比较；找到第一次不同；修复后换一组输入。这比只看最后的输出更容易发现原因。

小题保留函数外壳，先调用 checkout(2,12,3) 看日志，再换 checkout(3,10,5)，验证同一个修复能处理两笔订单。

#### 8 · 用断点暂停，亲眼看旧值变新值

这一步要用本地调试器，网页输出框不能代替变量面板。先运行 `npm run drill -- 05-08 --prepare`，再用 VS Code 打开项目和 `practice/steps/05-08.js`。

一种不需要新增配置文件的操作方式：

1. 在 VS Code 命令面板选择 **Debug: JavaScript Debug Terminal**，打开用于调试的终端。
2. 在这个终端输入 `node practice/steps/05-08.js`。程序遇到 debugger 语句会暂停；普通终端运行则通常不会暂停。
3. 看变量面板或把鼠标放在 number、total 上。第一次停下时应是 number=2、total=0。
4. 使用“单步跳过”执行加法，观察 total 变成 1，这已经偏离应得到的 2。再继续下一轮，确认错误会累积。
5. 修复加法，重新启动调试。第三次停在 debugger 时，number 应为 5、total 应为 5；执行加法后 total=10。
6. 最后退出调试，在普通终端运行 `npm run drill -- 05-08 --check`。再用空数组与一个数字验证。

也可以在普通终端使用 `node --inspect-brk practice/steps/05-08.js`，用 Chrome 的 chrome://inspect 连接 Node 调试进程后继续运行。inspect-brk 会先停在程序开头，需要继续运行到循环中的 debugger。只在本机使用这个命令。

暂停在某一行通常表示那一行还没执行。遇到函数调用，“单步跳入”进入内部，“单步跳过”先把调用执行完；调用堆栈能看是谁带你走到这里。自动验收检查计算是否正确，断点观察过程由你自己完成。

完成后，把这套方法用到综合存档题：正常存档走哪里，坏文本在哪里转入 catch，合法的非数组在哪里回退为空数组？不要只记“加一个 catch”这个答案。
