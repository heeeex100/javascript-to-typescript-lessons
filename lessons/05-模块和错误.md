# 05 · 给坏掉的存档加一层保护

今天做出来的效果：**读入 JSON 存档，遇到坏文本或非数组时返回空列表。**

<!-- foundations:start -->
## 一步一步看懂，再拆开练

一次只看一小步。先运行具体代码、逐行看值怎样变化，做几个小练习后再组合成主挑战。

### 存档先是一段文字，读出来还要检查

文件里写着 [1,2]，不等于程序已经拿到了数组。先把“文本读成值”做成功，再故意读坏文本，最后才加保护。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```js
const saved = JSON.stringify({ title: "复习" });
console.log(typeof saved);
const task = JSON.parse(saved);
console.log(task.title);
```

原例可在终端运行：`npm run concept -- 05`。

#### 2 · 一行一行看它做了什么

第一行把任务对象转换成适合保存的文字。第二行输出 string，说明 saved 中放的是文本。你可以额外 console.log(saved)，会看到带双引号的字段内容。

第三行 JSON.parse(saved) 读这段文本，得到真正的对象。第四行才可以使用 task.title，输出“复习”。

把 saved 的来源换成 "oops" 再解析，解析器会报错，因为它不符合 JSON 的格式。如果不处理，当前这段程序会在这里停下，后面的正常流程继续不了。

#### 3 · 改一点，再看一次

先只接住格式错误：

```js
try {
  const value = JSON.parse("oops");
  console.log(value);
} catch {
  console.log("存档格式坏了");
}
```

try 里正常运行时，catch 不会执行。try 里抛错时，跳到 catch，这里就有机会给用户反馈或选默认值。

然后把 "oops" 改成 "123"：这次没有报错，因为 123 是合法 JSON。可它不是任务列表！所以要再用 Array.isArray(value) 问“读出来的是数组吗”。一次检查格式，一次检查内容结构。

模块不用和 JSON 混着记：一个文件 export 一个函数，另一个文件 import 它，就是把写好的工具交给另一份文件使用。本关先完成存档保护，再打开 examples/js/05-modules.js 对照两个文件。

如果要保留自己的实验，先运行 `npm run concept -- 05 --prepare`，修改创建的文件，再用 `npm run concept -- 05 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

#### 4 · 分开练，先不做整道题

1. **先认识正常 JSON**：把文本转成数组并返回。
2. **先只处理格式坏掉**：正常 JSON 返回解析结果；遇到 oops 这样的坏格式返回 null。
3. **再问是不是数组**：不用解析，先实现 listOrEmpty：数组原样返回，null、数字和对象返回 []。

网页下方有对应的小练习。每次只做一题：先运行起点 → 修改 → 检查 → 说清变化。做对以后换下一题，不需要先把整个主挑战写完。TS 小练习显示本地文件和命令，由真实编译器检查。

#### 5 · 做过之后，再认识这些名字

把值写成可保存的文本叫**序列化**；把文本读回来叫**解析**。报错并跳出正常执行叫**抛出异常**。

JSON 只是一种文本格式。JSON.parse 成功不等于任务数据有效；完整字段校验会在第 17 关继续练。

做完小练习后，回主挑战把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。
## 本关小步练习

### 05-01 · 先认识正常 JSON

把文本转成数组并返回。

```js
function read(text) { return text; }
```

在实验台选择这道小题，或运行 `npm run drill -- 05-01 --prepare` 后编辑 `practice/steps/05-01.js`，再运行 `npm run drill -- 05-01 --check`。

<details>
<summary>一点提示</summary>

JSON.parse(text) 会读取符合 JSON 格式的文本。

</details>

<details>
<summary>试过后再看解释</summary>

```js
function read(text) { return JSON.parse(text); }
```

字符串看起来像数组，也仍然是字符串；解析才会得到数组值。

</details>

### 05-02 · 先只处理格式坏掉

正常 JSON 返回解析结果；遇到 oops 这样的坏格式返回 null。

```js
function safeRead(text) { return JSON.parse(text); }
```

在实验台选择这道小题，或运行 `npm run drill -- 05-02 --prepare` 后编辑 `practice/steps/05-02.js`，再运行 `npm run drill -- 05-02 --check`。

<details>
<summary>一点提示</summary>

catch 只会在 try 内发生抛错时执行。

</details>

<details>
<summary>试过后再看解释</summary>

```js
function safeRead(text) {
  try { return JSON.parse(text); }
  catch { return null; }
}
```

try/catch 为失败准备另一条路，但不会自动检查解析后的数据类型。

</details>

### 05-03 · 再问是不是数组

不用解析，先实现 listOrEmpty：数组原样返回，null、数字和对象返回 []。

```js
function listOrEmpty(value) { return value; }
```

在实验台选择这道小题，或运行 `npm run drill -- 05-03 --prepare` 后编辑 `practice/steps/05-03.js`，再运行 `npm run drill -- 05-03 --check`。

<details>
<summary>一点提示</summary>

Array.isArray(value) 回答“这个值是数组吗”。

</details>

<details>
<summary>试过后再看解释</summary>

```js
function listOrEmpty(value) { return Array.isArray(value) ? value : []; }
```

格式合法和内容符合要求是两次不同的检查。

</details>

## 每次只改一点

1. 先运行，观察正常存档之后在哪一行中断。
2. 给 JSON.parse 加 try / catch；失败返回 []。
3. 试“null”和“123”，它们没有语法错误，但仍不是列表。
4. 增加 Array.isArray 检查，再运行检查。

## 刚才发生了什么

JSON 是文本，JSON.parse 把它变成 JS 值。try / catch 在解析抛错时接住失败；结构检查处理“能解析但不是数组”的情况。本实验选择回退到空列表，正式项目也可以明确返回失败。
