# 10 · 拒绝乱填的任务标题

今天做出来的效果：**真实检查输入，只接受非空字符串，返回成功或失败结果。**

<!-- foundations:start -->
## 一步一步看懂，再拆开练

一次只看一小步。先运行具体代码、逐行看值怎样变化，做几个小练习后再组合成主挑战。

### 不知道传进来什么时，先问清楚再使用

一个函数可能收到文字，也可能收到 null 或数字。要求“未知输入都能安全处理”，就不能一上来调用 trim。先检查，再使用。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```ts
type ReadResult = { ok: true; value: number } | { ok: false; error: string };
function readCount(input: unknown): ReadResult {
  if (typeof input !== "number" || !Number.isFinite(input)) {
    return { ok: false, error: "需要有限数字" };
  }
  return { ok: true, value: input };
}
const result = readCount("3");
if (result.ok) console.log(result.value);
else console.log(result.error);
```

原例可在终端运行：`npm run concept -- 10`。

#### 2 · 一行一行看它做了什么

`input: unknown` 表示“任何东西都可能进来，目前还不确定”。不知道它是什么时，不能直接调用它的字符串方法。

例子先问 `typeof input !== "number"`：如果不是数字，就返回失败。`!Number.isFinite(input)` 还排除无效数字。只有这些判断都没挡住，后面才返回成功的数字。

返回结果有两种样子：成功有 ok:true 和 value；失败有 ok:false 和 error。不要把它们当成一个永远同时拥有两个字段的对象。

调用处先看 result.ok。成功分支读取 value，失败分支读取 error。例子传入 "3"，这是文字，所以打印“需要有限数字”。

#### 3 · 改一点，再看一次

先把调用里的 "3" 改成数字 3，观察分支和输出变化。再试 null 和 NaN。

接着故意在判断 ok 之前读取 result.value，编译器会提醒：失败结果根本没有这个字段。恢复到先判断再读取。

主挑战把这个做法换到标题文本：先问是不是字符串，再 trim，再问还剩不剩字。每一步只增加一个判断。

如果要保留自己的实验，先运行 `npm run concept -- 10 --prepare`，修改创建的文件，再用 `npm run concept -- 10 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

#### 4 · 分开练，先不做整道题

1. **先检查是不是文字**：只有字符串才返回去空格后的文本；其他输入返回空字符串。
2. **再按成功标记读字段**：成功时返回 value，失败时返回 error。
3. **最后拒绝空白标题**：只接受去空格后仍有字的字符串。

网页下方有对应的小练习。每次只做一题：先运行起点 → 修改 → 检查 → 说清变化。做对以后换下一题，不需要先把整个主挑战写完。TS 小练习显示本地文件和命令，由真实编译器检查。

#### 5 · 做过之后，再认识这些名字

把“可能是什么”用检查逐渐确定下来，叫**类型收窄**。`A | B` 表示可能是 A，也可能是 B，叫**联合类型**。

ok:true / ok:false 是辨别这次结果属于哪种情况的标记。unknown 要求先拿证据；any 则会让许多相关检查失效。

做完小练习后，回主挑战把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。
## 本关小步练习

### 10-01 · 先检查是不是文字

只有字符串才返回去空格后的文本；其他输入返回空字符串。

```ts
function clean(input: unknown): string { return input.trim(); }
```

在实验台选择这道小题，或运行 `npm run drill -- 10-01 --prepare` 后编辑 `practice/steps/10-01.ts`，再运行 `npm run drill -- 10-01 --check`。

<details>
<summary>一点提示</summary>

unknown 表示还没确定拿到什么。

</details>

<details>
<summary>试过后再看解释</summary>

```ts
function clean(input: unknown): string {
  if (typeof input === "string") return input.trim();
  return "";
}
```

检查之后，编译器才有依据允许字符串方法。

</details>

### 10-02 · 再按成功标记读字段

成功时返回 value，失败时返回 error。

```ts
type Result = {ok:true;value:string}|{ok:false;error:string};
function text(result: Result): string { return result.value; }
```

在实验台选择这道小题，或运行 `npm run drill -- 10-02 --prepare` 后编辑 `practice/steps/10-02.ts`，再运行 `npm run drill -- 10-02 --check`。

<details>
<summary>一点提示</summary>

if (result.ok) 或三元表达式都可以。

</details>

<details>
<summary>试过后再看解释</summary>

```ts
type Result = {ok:true;value:string}|{ok:false;error:string};
function text(result: Result): string { return result.ok ? result.value : result.error; }
```

标签把成功字段和失败字段区分开。

</details>

### 10-03 · 最后拒绝空白标题

只接受去空格后仍有字的字符串。

```ts
function accepted(input: unknown): boolean { return typeof input === "string"; }
```

在实验台选择这道小题，或运行 `npm run drill -- 10-03 --prepare` 后编辑 `practice/steps/10-03.ts`，再运行 `npm run drill -- 10-03 --check`。

<details>
<summary>一点提示</summary>

&& 右侧只会在左侧成立后执行。

</details>

<details>
<summary>试过后再看解释</summary>

```ts
function accepted(input: unknown): boolean { return typeof input === "string" && input.trim().length > 0; }
```

类型检查与业务检查各解决一层问题。

</details>

## 每次只改一点

1. 先运行，看到 unknown 不能直接调用 trim。
2. 使用 typeof 检查是否为字符串，非字符串走失败结果。
3. 增加空白检查，再运行 null、123 和空格输入。
4. 用 if (result.ok) 分别打印成功标题和失败原因。

## 刚才发生了什么

unknown 迫使你先取得证据。typeof 的分支把类型缩小到 string，这叫收窄。ok 的固定 true / false 又让成功与失败携带不同字段。
