## 一步一步看懂，再拆开练

一次只看一小步。先运行具体代码、逐行看值怎样变化，做几个小练习后再组合成主挑战。

### 先看总数怎样从 0 变成 3，再变成 8

今天先别管“累加器”“跨轮状态”。想象你在记账：本来 0 元，收到 3 元，再收到 5 元。我们把账面总数叫 total。先完全不写循环。

#### 1 · 先看这一个例子

先猜输出，再点运行。看不懂的行留到下一步逐行解释，不需要边看边查一串术语。

```js
let total = 0;
console.log("开始", total);
total = total + 3;
console.log("加了 3 后", total);
total = total + 5;
console.log("再加 5 后", total);
```

原例可在终端运行：`npm run concept -- 02`。

#### 2 · 一行一行看它做了什么

先运行，看见的是“开始 0 → 加了 3 后 3 → 再加 5 后 8”。重点盯着 `total = total + 3`，从右往左读：

1. 右边的 total 先取出旧总数 0。
2. 计算 0 + 3，得到新总数 3。
3. 等号把 3 放回左边的 total，以后再读 total 就是 3。

下一次 `total = total + 5` 同样先读旧的 3，所以得到 8。**等号在这里是“算完后保存”，不是问左右相不相等。**

| 到了哪一步 | 运算前的 total | 这次计算 | 运算后的 total |
| --- | --- | --- | --- |
| 创建总数 | 还没有 | 先记 0 | 0 |
| 加 3 | 0 | 0 + 3 | 3 |
| 加 5 | 3 | 3 + 5 | 8 |

对比 `total = 5`：这句话根本不读原来的 3，只是把总数改成 5。这就是“覆盖”和“在原来的基础上增加”的区别。

#### 3 · 改一点，再看一次

现在你已经会手写两次加法，才让循环替你重复。下面代码是另一个独立实验：

```js
const numbers = [2, 3, 5];
let total = 0;
for (const number of numbers) {
  total = total + number;
  console.log("这次的数", number, "加完的总数", total);
}
```

`[2, 3, 5]` 是一组按顺序放好的数。for...of 可以先读成：“每次从 numbers 拿一个数，暂时叫 number，然后做花括号里的事”。它依次拿到 2、3、5，因此三次加完总数依次是 2、5、10。number 不是永远等于 2，每轮拿到的值会换。

再试**故意写错**的版本：

```js
for (const number of [2, 3, 5]) {
  let total = 0;
  total = total + number;
  console.log(total);
}
```

输出变成 2、3、5。为什么？因为每次进入花括号，先重新执行 `let total = 0`。刚算的总数没有留给下一次。把这行放在循环前，就只会在一开始记一次 0。

最后才加条件：把加法放进 `if (number >= 3) { ... }`，就只有 3 和 5 加入，总数 8。`>= 3` 的意思是“是 3，或者比 3 大”；`> 3` 则不包括 3。

如果要保留自己的实验，先运行 `npm run concept -- 02 --prepare`，修改创建的文件，再用 `npm run concept -- 02 --local` 运行。HTML 保存后刷新浏览器。重复准备会保留你已有的文件。

#### 4 · 分开练，先不做整道题

1. **先加一次，不写循环**：total 初始为 0。只改第二行，让它把 3 加到已有总数上。
2. **接着再加一次**：第一步已经加了 3。修改最后一次赋值，保留这 3，再加 5，最终得到 8。
3. **让相同动作重复三次**：在循环内补上一次加法，让 total 最终等于 10。
4. **刚好等于也要算**：把 25 分钟也算达标。只改比较符号，让 qualifies(25) 为 true。
5. **加法只在条件成立时执行**：只累加大于或等于 3 的数：2 跳过，3 和 5 加入，总数为 8。
6. **换一组输入验证自己**：完成 sumAtLeast3，不写死结果。试普通列表、空列表、全不达标三种情况。

网页下方有对应的小练习。每次只做一题：先运行起点 → 修改 → 检查 → 说清变化。做对以后换下一题，不需要先把整个主挑战写完。TS 小练习显示本地文件和命令，由真实编译器检查。

#### 5 · 做过之后，再认识这些名字

先把下面六道小练习逐个做完，再回主挑战。它们分别练：加一次 → 再加一次 → 重复加 → 比较 25 → 有条件地加 → 换输入。

`total += number` 只是 `total = total + number` 的简写；看不顺眼时完全可以继续写长版本。

你刚才一直保存、不断加新的总数，常叫**累加器**。变量能在哪些地方读到，叫**作用域**。先记住具体规则：花括号里面用 let/const 创建的名字，外面不能直接读。等你真的碰到“找不到变量”的报错，再按花括号检查它创建在哪里。真假转换、&& 和 || 暂时不需要混在这一步学习。

做完小练习后，回主挑战把这些动作组合起来。若某一步仍说不清，就回到对应小题换一个数字再试；此时读更长的术语表帮助不大。

### 02-05 · 加法只在条件成立时执行

只累加大于或等于 3 的数：2 跳过，3 和 5 加入，总数为 8。

```js
const numbers = [2, 3, 5];
let total = 0;
for (const number of numbers) {
  total = total + number;
}
```

在实验台选择这道小题，或运行 `npm run drill -- 02-05 --prepare` 后编辑 `practice/steps/02-05.js`，再运行 `npm run drill -- 02-05 --check`。

<details>
<summary>一点提示</summary>

循环决定每个数都来看一次；if 决定这个数要不要加。

</details>

<details>
<summary>试过后再看解释</summary>


</details>

if 决定当前记录是否参与统计；for...of 逐条取记录。total 和 count 放在循环外，因此能累加。如果每轮都重新声明并置零，就无法记住上轮结果。
