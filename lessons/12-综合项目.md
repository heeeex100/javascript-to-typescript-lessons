### 纯函数、不可变更新与职责分离

**不可变更新**是保留旧数据、创建新结果的约定。它便于比较前后状态、实现撤销，并不表示整个 JS 运行环境禁止修改对象。

- **纯函数**对相同输入产生相同结果，并且不修改外部可观察状态；业务转换可以尽量这样写，打印、存盘等副作用留给调用方。
- **原地修改**：splice、push、sort 会改动原数组；filter、map 返回新数组。浅拷贝仍可能共享内部对象，修改字段时还要创建新对象。
- **索引与身份**：下标表示当前的位置，id 表示任务的身份。排序后位置变化，id 仍应稳定；findIndex 找不到时返回 -1，不能直接当有效删除位置。
- **结果约定**：返回成功的新列表或明确失败，让调用方决定显示什么。不要让“没找到”悄悄删除最后一项。
- **分层**：models 描述数据，validation 检查输入，service 实现规则，main 组织调用和展示。拆分是为了能单独理解和验证每一步。

<details>
<summary>读例子 → 改一个地方 → 检查理解</summary>

```ts
interface Item { id: number; done: boolean }
const before: Item[] = [{ id: 1, done: false }, { id: 2, done: false }];
const after = before.map(item =>
  item.id === 1 ? { ...item, done: true } : item
);
console.log(before[0].done, after[0].done);
console.log(before === after, before[1] === after[1]);
```

**逐步理解**：输出“false true”“false true”。只复制需要修改的对象，没变的对象仍共享引用。这能保留旧状态，但要求后续也遵守不直接修改共享对象的约定。

**动手试一试**：把 map 中新建对象的部分改成直接赋值 item.done = true，再比较 before；观察为什么只换数组容器不够。

1. 运行后比较删除结果与原列表，原列表怎么也变了？
2. 改用 filter 生成新数组，保留原列表。

5. 最后把功能接入 project/service.ts 和 main.ts，运行 npm run demo。

## 刚才发生了什么

splice 直接修改原数组；filter 创建新数组。Result 让不存在的 id 有明确失败路径。把数据操作与显示分开，就能单独检查不修改输入等业务约定。
