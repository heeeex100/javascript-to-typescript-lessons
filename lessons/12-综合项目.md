## 边看边练

### 改一份结果，为什么旧数据也跟着变了

任务页面想保留修改前的列表，用来比较或撤销。只换一个变量名不够；要确认是否还在改同一个对象。这个例子只把一项标记为完成。

#### 1 · 先保留旧数组，再练删除

```ts
interface Item { id: number; done: boolean }
const before: Item[] = [{ id: 1, done: false }, { id: 2, done: false }];
const after = before.map(item =>
  item.id === 1 ? { ...item, done: true } : item
);
console.log(before[0].done, after[0].done);
console.log(before === after, before[1] === after[1]);
```

原例可在终端运行：`npm run concept -- 12`。

before 放着两项任务。map 逐项看：id 是 1 时，创建 `{ ...item, done:true }` 这个新对象；不是 1 时，沿用那项对象。

第一组输出 false true：before 的第一项仍没完成，after 的第一项已完成。说明这次修改没有把旧第一项也改掉。

第二组输出 false true：两个数组不是同一个；但没修改的第二项仍是同一个对象。这是有意保留没变的部分，不表示每项都被完整复制。

如果把声明改成 const after = before，再改 after[0].done，就会同时看到 before 也变了。两个名字可能读到同一个东西，这就是要实际检查的地方。


`条件 ? A : B` 是根据条件选择一个值的表达式，只有被选中的一边会执行。例子里 `item.id === 1 ? 新对象 : item` 可改成 `if (...) return 新对象; return item;`，结果相同；这不是在字段名后写可选属性的问号。

综合题的 `Result<Task[]>` 先把 Task[] 理解为任务数组，再把它放进 Result 这份通用结果类型中。尖括号描述类型之间的关系，真正成功的值仍要用 `{ ok: true, value: 新数组 }` 创建，类型名本身不能替你生成结果。

#### 2 · 找不到时不要误删

用一份独立输入观察“没有匹配项”的删除结果：

```ts
interface Item { id: number; done: boolean }
const before: Item[] = [{ id: 1, done: false }, { id: 2, done: false }];
const after = before.filter(item => item.id !== 99);
console.log(before.length, after.length);
console.log(before === after);
```

输出 2、2 和 false：原数组保留，新数组内容也保留。小题只要求不误删；综合题的接口还要求找不到时返回失败，两者的返回约定不同。

把本段过滤条件中的 99 改成 1，得到去掉第一项的新数组；再观察 before 仍是两项。filter 返回符合条件的项，!== 1 表示留下编号不是 1 的项。

对比 splice：它直接改原数组。更要注意 findIndex 找不到时是 -1，splice(-1,1) 会删最后一项，正好违背“找不到就失败”。

如果目标不存在，应该返回失败，原数组也应该保留。这和删除成功后返回新数组是两条不同的执行路径。


##### 就地小练习 12-02 · 找不到时不要误删

沿用 filter，让目标不存在时所有数据保持。

```ts
function remove(ids: number[], target: number): number[] { const out=[...ids]; out.splice(out.indexOf(target),1); return out; }
```

#### 3 · 只替换要变的对象

下面才是“修改完成状态”的例子：

```ts
interface Item { id: number; done: boolean }
const before: Item[] = [{ id: 1, done: false }, { id: 2, done: false }];
const after = before.map(item => item.id === 1 ? { ...item, done: true } : item);
console.log(before[0].done, after[0].done);
console.log(before === after);
```

输出 false、true 和 false。新数组中的第一项是新对象，原数组与原对象都没有被修改。

保留旧数据、创建新结果的约定叫**不可变更新**。不修改外部数据、只根据输入算结果的函数更容易单独验证。

readonly 能帮你在编译期发现一些直接写入，但它不会在运行时自动深度冻结对象。先证明 before 没变，再考虑用类型约束辅助。


`tasks: readonly Task[]` 要求函数不要通过这个参数增删或替换数组元素，所以 tasks.push、tasks.splice 会被类型检查拦住；但它并不等于每个 Task 的所有字段也只读。直接修改 tasks[0] 中的对象仍可能影响调用方，是否允许要看对象类型与任务要求。返回新数组和新对象，才是这里保留原数据的实际做法。

##### 就地小练习 12-03 · 只替换要变的对象

把 id=1 的 done 改为 true，返回新对象，保留 before。

```ts
const before={id:1,done:false};
const after=before;
after.done=true;
```

## 综合大练习：删除任务或改标题，同时保留旧列表

**实现删除与改名两个操作：成功给出新列表，失败说明原因。**

### 题目要求

- removeTask(tasks,id) 删除任务，renameTask(tasks,id,title) 修改标题。成功返回 {ok:true,value:新列表}。
- 编号不存在，或新标题去空格后为空时，返回 {ok:false,error:原因}。原数组与原任务对象保持不变。

### 输入与预期结果

原列表为 id=1 标题 A：重命名为 B 后，新列表显示 B，原列表仍显示 A；编号不存在时返回 ok:false。
