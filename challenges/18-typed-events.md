### 发布订阅、keyof 与事件载荷类型

**发布订阅**把“事件发生”与“谁响应事件”分开：on 注册监听器，emit 通知监听器，取消订阅函数移除对应注册。它适合让保存任务的逻辑不用直接调用每一个界面组件。

- **事件名与载荷**：例如 saved 对应任务对象，failed 对应错误消息；这是一张映射表。事件名正确、数据错误也必须被类型检查发现。
- **keyof**取得对象类型的属性名集合；`K extends keyof Events` 限定 K 必须是合法事件名。
- **索引访问类型**：`Events[K]` 取得当前事件名对应的载荷类型。参数 event: K 与 payload: Events[K] 使用同一个 K，表达两者的关联。
- **函数类型**：`(payload: Events[K]) => void` 描述监听器；`() => void` 描述不接收参数的取消订阅函数。void 表示调用方不使用返回值。
- **派发快照**：通知时复制本轮监听器列表，让通知期间的新增和取消不扰乱当前轮次。具体行为以本关合同为准；取消操作重复执行应安全。

```ts
interface Signals {
  saved: { id: number };
  failed: { message: string };
}
function describe<K extends keyof Signals>(event: K, payload: Signals[K]): void {
  console.log(event, payload);
}
describe("saved", { id: 7 });
describe("failed", { message: "离线" });
// describe("saved", { message: "离线" }); // 取消注释看类型错误
```

**逐步理解**：K 从事件名推断；saved 的载荷必须提供 id，failed 的载荷必须提供 message。此处只演示类型关系，订阅存储与通知由你在练习中实现。

## 本关需求就是你的验收合同

- createEmitter<Events>() 提供 on(event,listener) 和 emit(event,payload)。事件名与载荷由 Events 的键和值对应。
- on 返回取消函数；可重复取消，不影响其他订阅。同一回调注册两次视为两份独立订阅。
- emit 同步按注册顺序派发；每次开始时复制订阅快照。本轮新增下轮生效，本轮删除不影响本轮快照。
- 没有订阅者时不抛错；不同实例彼此隔离。
- 基础合同假定监听器不会抛错、不递归 emit；监听器异常隔离作为扩展。
- 测试需要错误事件名、错误载荷在编译时失败，不能将公开参数退化为 any。本关事件名使用 saved / failed / tick 等普通自有键。

## 做完之后再给概念命名

泛型在这里表达了事件名和数据之间的联系。映射类型把不同键对应到不同监听器类型。运行时的快照又决定了注册表变更何时生效。@ts-expect-error 用于负向类型验收：预期错误若没有发生，检查反而失败。
