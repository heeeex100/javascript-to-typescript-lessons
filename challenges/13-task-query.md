### 数据处理管道、排序与分页

**数据处理管道**把一个查询拆成几步，每步接收上一阶段的结果。任务列表通常先筛选、再排序、最后分页；顺序会影响返回的数据含义。

- **筛选条件**同时满足时可用 &&；关键词可能先 trim 和统一大小写，再用 includes 匹配。空关键词是否代表不过滤，要遵守本关合同。
- **比较器**：sort 的回调返回负数表示 a 在 b 前，正数表示 a 在 b 后，0 表示相等排序位置。数字升序常写 `(a, b) => a - b`；没有比较器时会按字符串方式排序。
- **避免修改输入**：sort 原地修改；可先复制再排。filter 已创建新数组，但内部对象仍共享，不能顺手改字段。
- **分页**：从第 1 页开始时，起点为 `(page - 1) * pageSize`；slice 的结束位置不包含在结果中。total 通常是筛选后、分页前的数量。
- **确定性**：主排序字段相同时，合同可能要求按 id 进一步排序；这样多次查看不会因为输入顺序而产生不明确结果。

<details>
<summary>读例子 → 改一个地方 → 检查理解</summary>

```js
const durations = [12, 3, 25, 8];
const matched = durations.filter(value => value >= 8);
const ordered = [...matched].sort((a, b) => a - b);
const page = 2;
const size = 2;
console.log(ordered.slice((page - 1) * size, page * size));
console.log(matched.length, durations);
```

**逐步理解**：排序后为 [8, 12, 25]，第二页只有 [25]，筛选总数为 3。原始 durations 仍是 [12, 3, 25, 8]。

**动手试一试**：先对原数组分页再筛选，比较返回哪些值；把 size 改成 1，画出每页的起止位置。

## 先复现一个真实问题

1. 先运行：搜索 js、每页 1 项，为什么第一项不是优先级更高的任务？
2. 先只做搜索和状态筛选，打印中间列表。
3. 加入排序，再分页；用 page 2、page 99 试边界。
4. 跑检查，最后确认原数组顺序没有改变。

## 本关需求就是你的验收合同

- 数据已满足 {id,title,done,priority} 结构；priority 越大越靠前。
- 关键词 trim 后忽略大小写，按标题包含匹配；空关键词匹配全部。
- status 仅允许 all / pending / done。排序先按 priority 降序，同分按 id 升序。
- page 从 1 开始；page、pageSize 必须为正安全整数，否则抛错。
- 返回 {total,items}；total 是筛选后分页前的数量。超出末页返回空 items。
- 不得修改输入数组、对象或 options。
