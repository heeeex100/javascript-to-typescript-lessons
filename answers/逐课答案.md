# 逐课答案与思路

先完成练习，再看这里。参考实现并不是唯一正确写法；检查输入、输出和边界是否符合约定。

## 00 · 环境

代码保存到 `.js` 文件；终端输入 `node 文件路径`；console.log 输出显示在该终端。Node 执行程序，npm 管理依赖和脚本，tsc 检查与编译 TS。

## 01 · 值与转换

`"5" + 1` 是字符串 `"51"`，`Number("5") + 1` 是数字 6，`"5" === 5` 为 false。const 不允许绑定指向另一个值，但对象内容可以改变。

parseMinutes 先检查输入是非空文本，再转换，最后检查是否有限、非负。只检查 NaN 不够，因为 Infinity 也不该被当作有效分钟数。实现见 `js.js`。本题接受 Number 能解析的数字形式（含小数），不是“只允许十进制数字字符”的格式校验题。

## 02 · 条件与循环

```js
const sessions = [10, 25, 40, 15];
let total = 0;
let count = 0;
for (const minutes of sessions) {
  if (minutes >= 25) {
    total += minutes;
    count += 1;
  }
}
console.log(total, count); // 65 2
```

空数组得到 0 和 0。把 >= 改为 > 后得到 40 和 1。把 total 放到循环里会每轮重新初始化，且块外无法访问该绑定。

## 03 · 函数

`const square = value => value * value`；`apply(4, square)` 得到 16。传入的是函数值，apply 内部再调用。闭包让同一个计数器保存其 count；再次调用工厂函数会得到新的 count。

## 04 · 集合

pendingTitles 用 filter 决定保留谁，再用 map 得到标题。completeTask 用 map 保留数组结构，在匹配分支返回新对象；未匹配项可复用原对象，因为没有修改它。实现见 `js.js`。

浅拷贝只复制第一层属性值。属性值如果是对象引用，复制后仍指向同一个对象。

## 05 · 模块与错误

导入路径相对于正在导入的源文件。合法 JSON 可以是数字、null、字符串等，解析成功不代表符合任务结构。解析 oops 时抛错并进入 catch；合法对象文本可继续访问字段。

## 06 · 异步

成功路径顺序为 A → B → C。async 函数返回 Promise，await 等待其结果。模拟失败时没有成功结果，走 catch；try 内如果没有 await 一个后续会拒绝的 Promise，那个拒绝不一定被当前 catch 接住。

两次操作相互独立时可同时启动再 Promise.all；后一项依赖前一项结果时需要顺序处理。

## 07 · DOM 扩展练习

在 HTML 的 form 后添加：

```html
<label><input type="checkbox" id="pending-only">只看未完成</label>
```

在 app.js 的元素查询区域加入：

```js
const pendingOnly = document.querySelector("#pending-only");
pendingOnly.addEventListener("change", render);
```

render 中将遍历 tasks 的部分改为：

```js
const visibleTasks = pendingOnly.checked ? tasks.filter(task => !task.done) : tasks;
for (const task of visibleTasks) {
  // 保留原有创建 li、span、button 的逻辑
}
```

如果复选框因通用 input 样式变大，可加 `input[type="checkbox"] { min-width: auto; flex: none; }`。筛选不修改 tasks，因此取消勾选仍能看到完成项。

## 08 · 编译

`function square(value: number): number { return value * value; }`。传入 `"4"` 在检查阶段失败；传入 `Number("4")` 得到 16。类型标注通常在生成 JS 时被移除，不会自动做转换。

## 09 · 对象类型

`interface User { id: number; name: string; email?: string }`。读取 email 要考虑 undefined。formatTask 实现见 `ts.ts`；可选备注先 trim，空备注不添加括号。

## 10 · 收窄

parseTitle 先排除非字符串和空文本，再返回成功。不要使用 `String(value)` 随意把 null 转成标题 `"null"`。外部输入是 unknown，靠运行时检查逐步获得可用类型；断言 as 不会执行这些检查。

## 11 · 泛型

T 代表某次调用的元素类型。`T extends { id: number }` 确保函数能使用 id，返回 T 则保留其他字段类型。找不到时返回 undefined；实现见 `ts.ts`。

## 12 · 删除功能

removeTask 实现见 `ts.ts`。先用 some 判断存在，再用 filter 创建新数组。不存在则返回失败，原数组不会被修改。

最后一课问题：TS 中仍保留 JS 的函数、流程、数据和异步行为；运行时输入必须单独校验；返回新数组便于确认每一步数据变化；只有多个参数或返回值之间需要保留类型关系时，泛型才体现价值。
